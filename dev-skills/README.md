# 开发 Skill 包（dev-skills）

> 这个作品从想法到样机、到路演材料，**99% 的代码与图由 AI 生成**。
> 这里把整条流程拆成 8 个 Skill —— 不是文档，是**给编码 Agent 直接执行的工序**。
> 任意一个 AI 硬件项目，照着跑一遍就能复刻出同类原型。

## 和 `skills/` 的区别

| | `skills/` | `dev-skills/`（本目录） |
|---|---|---|
| 给谁用 | **产品运行时的 Agent**（设备上的 ai_agent） | **开发期的编码 Agent**（Codex / Claude Code / CodeBuddy） |
| 干什么 | 哄睡、夜醒陪护、晨间复盘 | 调研、写需求、选型、画图、写固件、做前端、做海报 |
| 例子 | `sleep-onset.md` | `backend/SKILL.md` |

两套互不干扰，一套造产品，一套造另外一套。

## 流水线

```
 ①产品调研 ──► ②需求分析 ──► ③硬件设计 ──► ④图纸设计
                                    │              │
                                    └──► ⑤后端 ────┴──► ⑥前端设计
                                                          │
                                                          └──► ⑦视觉/路演
                     ▲                                            │
                     └──────────── ⑧ 编排器全程调度 ◄─────────────┘
```

| # | Skill | 输入 | 产出 | 何时进入下一环 |
|---|---|---|---|---|
| ① | [product-research](product-research/SKILL.md) | 一句话想法 + 目标生态 | 赛道验证 / 生态位地图 / 竞品矩阵 | 找到空白生态位，且数据都有来源 |
| ② | [requirements](requirements/SKILL.md) | ①的结论 | PRD（含三个不做、北极星指标） | 每条需求都能变成可测断言 |
| ③ | [hardware](hardware/SKILL.md) | PRD 的形态与传感需求 | 形态方案、选型表、BOM、结构红线 | BOM 达标、引脚冲突清零 |
| ④ | [drawing](drawing/SKILL.md) | ③的尺寸与材质 | 三视图（写实渲染 + 精确标注） | 三视图比例自洽、标注可读 |
| ⑤ | [backend](backend/SKILL.md) | PRD 的行为规则 | 固件核心层 + PC 网关 + 测试 | 断言全绿 + 真机链路跑通 |
| ⑥ | [frontend](frontend/SKILL.md) | PRD 的交互与养成设定 | 单文件可运行原型 | 全流程真实可跑、无 JS 错误 |
| ⑦ | [poster](poster/SKILL.md) | ①-⑥全部产物 | 路演 PPT / 海报 / 演示视频 | 视觉审查通过、数据有口径 |
| ⑧ | [orchestrator](orchestrator/SKILL.md) | 一句话需求 | 调度上面 7 个 Skill | 每阶段验收门全过 |

## 小白怎么用（三步）

1. **说清楚一句话**：给 Agent 一句"我要做一个 XX"的产品描述，附上目标人群和使用场景。
2. **说"按 dev-skills 跑"**：Agent 读 `orchestrator/SKILL.md`，按顺序调用其余 7 个，
   每完成一个阶段停下来给你验收物（一张对照表 / 一份 PRD / 一张三视图 / 一个能点的原型）。
3. **只做决策，不做实现**：你的活是回答"选 A 还是选 B""这个数字准不准"，
   其余交给 Skill。

## 三条贯穿全程的铁律

1. **数字必须有出处或标注为估计**。没验证的说没验证，编一个数就毁掉整场的可信度。
2. **模拟与实测分栏写**。固件跑通 ≠ 产品验证；合成信号 ≠ 真人标定。混着写就是造假。
3. **每个阶段都要有可验证的验收物**，不接受"应该没问题"。
