# Orchestrator · 让 Agent 自己编排整条产线

**一句话：把"我要做个 XX"拆成 7 道工序，每道工序有输入、有产出、有验收门。**

## When to use

- 用户给了一句话产品想法，没说从哪开始
- 用户说"按 dev-skills 跑""复刻一套"
- 多阶段任务需要判断"现在该做哪一步""是不是可以进下一步"

## How to use

### 第 0 步：锁定三件事（只问这三个，别多问）

1. **给谁用**：目标用户 + 具体场景（"25-35 岁高压上班族，躺下就想事情"）
2. **形态边界**：是否有硬件？桌面/床头/穿戴？有没有不能做的东西
3. **验收方式**：比赛路演 / 内部立项 / 给投资人 / 自己玩

> 用户答不全就自己给默认值并**明确说出默认值**，不要卡在提问上。

### 第 1 步：按阶段推进，每阶段一个 gate

| 阶段 | 调用 | 交付给用户看的东西 | Gate（不过不许进下一阶段） |
|---|---|---|---|
| 1 | product-research | 生态位地图 + 竞品矩阵 + 3 条结论 | 每个数字有来源；能找到一处"无人占位" |
| 2 | requirements | PRD v0.1（含三个不做） | 每条需求可转成一条可测断言 |
| 3 | hardware | 形态方案 2-3 个 + 选型表 + BOM | BOM 在预算内；引脚/功耗/声压三项无冲突 |
| 4 | drawing | 三视图（正/侧/俯 + 尺寸标注） | 三视图比例自洽；标注数字与选型表一致 |
| 5 | backend | 核心层 + 网关 + 测试报告 | 断言全绿；真机链路有实测数据 |
| 6 | frontend | 单文件可运行原型 | 全流程真实可跑；零运行时错误 |
| 7 | poster | 路演 PPT + 演示视频 + 答辩预案 | 视觉审查两轮通过；数据口径成文 |

### 第 2 步：阶段间的三条硬规则

1. **不许跳步**：图纸尺寸必须来自硬件选型，演示视频必须来自真跑的原型。
2. **不许带病前进**：某阶段 gate 不过，就先修，不要"后面再说"。
3. **每阶段结束必须落盘**：文档、图片、代码都进仓库，附一句"这一版能证明什么、不能证明什么"。

### 第 3 步：失败时的回退表

| 症状 | 先查 | 回退到 |
|---|---|---|
| 说不出差异点 | 生态位地图是不是只有一层 | ① 重做分层 |
| 功能列表越来越长 | 有没有写"三个不做" | ② 砍到只剩核心回路 |
| BOM 超预算 | 是不是每个部件都选了旗舰 | ③ 降规格或换方案 |
| 图纸和实物对不上 | 尺寸是不是从渲染反推的 | ④ 用设计目标值重标 |
| 演示时某一夜跑不完 | 是不是用倍速硬等真实时钟 | ⑥ 改成脚本化演示时间线 |
| 答辩被问住 | 有没有写"如实"边界 | ⑦ 补答辩预案的"绝不说"清单 |

## 并行与合并

- ① 与 ② 之间强串行（调研结论决定需求）
- ③ 与 ④ 半并行：形态定了就先出草图，选型落定后再出正式三视图
- ⑤ 与 ⑥ 可并行：固件跑规则时，前端可以先做交互壳，用同一份规则表
- ⑦ 必须等 ⑤⑥ 有真实产物（截图/视频）才能做，否则就是画饼

## 给 Agent 的启动模板

```
目标：<一句话产品>
用户与场景：<谁、什么时候用、现在怎么解决>
边界：<必须有 / 绝对不做>
验收：<比赛/立项/投资>
任务：读 dev-skills/orchestrator/SKILL.md，按阶段执行。
      每阶段结束输出：产出物路径 + 本阶段能证明什么 + 不能证明什么 + gate 是否通过。
      未通过就停下来告诉我卡在哪，不要自行降标准。
```

## Important

- **别一次性把所有阶段做完再给我看**——每阶段交付一次，用户才好纠偏。
- **别忘了写"不能证明什么"**：这是这套流程里最值钱的一句话，路演和答辩都靠它兜底。
- **非技术用户在场时**，每阶段用一句人话总结（"这块证明了你的设备能听见你说话"），
  再给技术细节。
