# 前端设计 · 单文件也要像真产品

**一句话：演示时评委只看两件事——它真的在动，和它有没有骗人。**

## When to use

- 做产品交互原型（比赛/立项/给投资人看）
- 要真语音、真音频合成、真养成数据
- 需要一个能塞进任何壳（WebView/Electron/小程序）的产物

## 架构：单文件零依赖

```
m.html
  ├─ <style>    设计令牌（CSS 变量：底色/强调色/文字/线）
  ├─ <body>     屏幕结构（固定画布 + 覆盖层）
  └─ <script>   状态 + 规则 + 音频 + 语音 + 存档
数据：localStorage（键名统一前缀，如 sle_*）
```

为什么这样做：**打开即用**。没有构建、没有后端、没有依赖，
评委的电脑上双击就能跑；要嵌壳也只换一层容器。

代价：文件会到 140KB+。所以要**按区块注释分隔**（音景 / Agent / 语音 / 养成 / 学习 / 闹钟），
否则改一处要翻半天。

## 三个"真"原则（决定它像不像真产品）

1. **真音频**：不要放录音循环，用 Web Audio 实时合成（本案五层混音 + 卷积混响）。
   录音循环听三遍就露馅，合成的声音永不重复。
2. **真状态**：三围/等级/金币/睡眠分期都来自真实数据与规则，不是随机数。
3. **真存档**：刷新不丢、清档等于新用户。所有键名列表写进文档。

## 演示模式：必须做成脚本化时间线

**这是本案最有价值的一条经验。**

第一版"×20 倍速"在路演里根本不可用：倍速只加速计时器，
但日出是按**真实时钟**触发的（明早 07:00）——一整夜 ÷20 仍要 54 分钟。

正确做法：**单独写一条脚本化时间线**，25 秒演完整夜：

```js
function demoTour(){
  tourClear(); state.session = { demo:true, ... };
  tourLater(3,  ()=>{ sim.stage='浅睡'; ... });
  tourLater(7,  ()=>{ sim.stage='深睡'; ... });
  tourLater(9,  ()=>{ session.masked++; });      // 演一次噪音遮蔽
  tourLater(12, ()=>{ sim.stage='REM'; ... });
  tourLater(17, ()=>{ session.wakes++; });       // 演一次夜醒陪护
  tourLater(20, ()=>{ demoSpeed=10; sunrise(); });
  tourLater(27, ()=>{ clearTimers(); goTab('report'); });
}
```

配套要点：
- 报告用 `session.demo` 标记按"一整夜"出数（7h12m / 深睡 31%），
  否则 25 秒会被算成"3 分钟睡眠"
- 中途退出要 `clearTimers()`，否则长间隔（日落渐暗 480s）还在跑，
  结束后 8 分钟又盖一层夜色
- 演示态的遮罩用**压暗**（0.42）而不是纯黑（1.0）：真实流程夜里是全黑熄屏，
  但演示要让评委看见阶段在变

## 六个真实 bug（照抄这六条能省一天）

| 现象 | 成因 | 防法 |
|---|---|---|
| 分数显示成 `67.083333...` 溢出圆环 | 评分公式没取整 | 所有展示数值 `Math.round`；CSS 加 `max-width + ellipsis` 兜底 |
| 演示后整页发橘 | 日出只清 `ovDark`，没清 `ovSunset` | 状态切换时**清全部覆盖层**，别只清记得的那个 |
| 结束后按钮还是"结束今晚" | 收尾没复位文案 | 每个终态都写"UI 复位"分支 |
| 重复计夜、重复发币 | 结算函数没有防重入 | `if(!s || s.done) return; s.done = true;` |
| 设置页填了 key 重启后没了 | 保存与读取用了两套键名 | 键名常量化，读写同一常量 |
| 演示加速"点了没反应" | 监听 `pointerdown`，测试用 `click()` | 手动派发 `new PointerEvent('pointerdown')`；真机上本就正常 |

## QA 方法（不靠肉眼猜）

```js
// 1) 挂错误收集
window.__errs=[]; addEventListener('error', e=>__errs.push(e.message));
// 2) 清档 → 走首开 → 逐功能调用
localStorage.clear(); location.reload();
// 3) 断言要贴代码契约，别贴直觉
//    反例：用 innerText 判断改名生效——隐藏页的文字不在 innerText 里
//    正例：读 localStorage 的键 + 读目标元素的 textContent
// 4) 录屏抽帧看状态：ffmpeg -ss 12 -i demo.webm -frames:v 1 f.png
```

> 抽帧能发现读代码发现不了的问题（本案"演示时屏幕没进夜景"就是抽帧才看出来的）。

## 交互与文案

- 无屏/少屏产品的原则：**晚上要能闭眼操作**，语音优先，按钮兜底
- 文案短句、不报菜单、不说教（"我在，别急着看手机" > "已启动夜醒陪护模式"）
- 数字要有单位与上下文（"+30 金币 · 按时起床" > "+30"）

## 验收门

- [ ] 双击本地文件即可打开（无构建）
- [ ] 刷新不丢数据；清档等于新用户
- [ ] 音频是实时合成，不是循环文件
- [ ] 演示模式 30 秒内能演完整夜，且报告数值合理
- [ ] 全流程零 JS 运行时错误（用 `__errs` 收）
- [ ] 收尾状态复位（按钮文案、覆盖层、定时器）
- [ ] 关键页面截图 + 一段录屏可交付
