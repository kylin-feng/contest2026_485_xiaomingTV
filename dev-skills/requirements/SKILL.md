# 需求分析 · 只写能被验证的需求

**一句话：一份好的 PRD，能让开发者直接写出断言，能让评委直接挑刺。**

## When to use

- 要写 PRD / 产品设计文档
- 功能越加越多，需要砍
- 要给硬件、固件、前端同时派活

## How to use

### 第 1 步：写"一句话产品"

格式：**`<形态>` 里的 `<东西>` —— `<它解决谁在什么时刻的什么问题>`**

本案：住在一台复古掌机里的 AI 哄睡电子宠物——会聊天、会讲故事、
会督促睡觉、整夜值守音景。

自检：去掉形容词后还成立吗？如果只剩"一个 App"，说明没找到形态价值。

### 第 2 步：定"一条核心回路"（其它全是它的输入输出）

不要并列三个核心功能。写成一个环：

```
感知 → 记忆 → 决策 → 执行 → （传感器回读）→ 感知
```

本案：Agent 每 3 秒一轮；入睡判定是**输入端**，光/声引导是**输出端**，
三者不是三个功能，是"一个核心 + 它的两端"。

### 第 3 步：写"三个不做"（最重要的一节）

每个"不做"要带理由，理由要能被评委复述：

| 不做 | 理由 |
|---|---|
| 不做屏幕 | 睡前一小时不应有屏幕（产品哲学） |
| 不做摄像头 | 卧室隐私红线，物理上不存在 ≠ 可以关闭 |
| 不做单品（床垫/戒指） | 那里已有强玩家，我们做它们的"指挥" |

> 没有"不做"的产品，最后什么都有，什么都不强。

### 第 4 步：指标设计（北极星 + 反向）

- **北极星**：一个能变化的用户状态量。本案：入睡潜伏期，连续 4 周缩短 20%
- **次指标**：留存 / 订阅转化 / 互动率 / 报告打开率
- **反向指标**：你的产品**别把人烦到**。本案：误干预否决率 < 2%，
  Agent 不能变成新的打扰源

> 只写正向指标的产品，一定会在某个夜晚把用户吵醒。

### 第 5 步：状态机 + 异常路径

把一夜（或一个使用周期）写成状态机，**每个状态写"进得去、出得来"**：

```
待机 → 日落陪伴 → 入睡护航 → 深睡守护 ⇄ REM → 日出唤醒 → 晨间报告 → 待机
                     ↘ 夜醒陪护（任意睡眠态可进入，10 分钟无响应回落）
```

异常路径必须写（每条都要有明确行为）：
- 传感器丢失 / 离床超时
- 网络中断（降级为本机动作）
- 误触发保护（同一规则 10 分钟内最多 3 次）
- 用户强行打断（物理手势优先级最高）

### 第 6 步：把需求写成可测断言

每一条都要能回答"怎么证明它做到了"：

| 需求 | 可测断言 |
|---|---|
| 噪音上来要遮住 | 环境 > 45dB 时遮蔽层 +12%，上限 50%，安静后 5 分钟缓收 |
| 入睡后要闭嘴 | 呼吸 < 10 次/分且进入浅睡 → 启动 20 分钟渐弱 → 静默 |
| 夜醒不能亮屏 | 夜醒事件触发后 0 次屏幕点亮 |

## PRD 骨架（12 章精简版）

1 引言与背景 · 2 定位与目标 · 3 市场与竞品（引调研） · 4 用户与场景 ·
5 产品方案（形态/硬件/Agent/软件） · 6 交互与时间轴 · 7 隐私与安全 ·
8 商业模式 · 9 计划与里程碑 · 10 验证指标 · 11 风险与对策 · 12 附录

## Important · 口径诚实

文档里必须**分栏写清**：

- **已验证**：真机跑过 / 实测数据 / 断言数量
- **模拟**：算法用合成信号验证，真人标定未做
- **假设**：还没验证的用户行为

> 本案写法："混淆矩阵 TP38/FN0/FP0/TN81（**合成信号**）；真人整夜标定还没做，报告里标了。"
> 这一句比多写十个功能都值钱——评委信的是这个。

## 验收门

- [ ] 有一句话产品定义，去掉形容词仍成立
- [ ] 核心回路画得出来，且只有一个
- [ ] 三个"不做"各带理由
- [ ] 北极星 + 反向指标都有
- [ ] 状态机每个状态都有退出路径
- [ ] 至少 4 条异常路径写明行为
- [ ] 每条核心需求都有可测断言
- [ ] 已验证 / 模拟 / 假设 三类信息分开标注
