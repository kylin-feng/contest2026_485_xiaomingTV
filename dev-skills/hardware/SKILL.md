# 硬件设计 · 先把红线画好，再谈造型

**一句话：能用 300 块的器件做出 3000 块的体验，才算会做硬件。**

## When to use

- 定形态（球/半球/柱/薄片）与尺寸
- 选传感器与执行器
- 出 BOM、估成本
- 规划从开发板到小批量的路线

## How to use

### 第 1 步：形态服从场景，不服从好看

| 场景 | 形态建议 | 理由 |
|---|---|---|
| 床头柜 | 球形/半球（⌀100-130mm） | 无方向性、拾音均匀、放在床头不占位置 |
| 书桌 | 柱形/薄片 | 有背面、可贴墙 |
| 随身 | 圆角卡片/腕带 | 无尖角、可穿戴 |

**形态可以故事化**：本案最终选精灵球球体——
"赤道环"正好是 1800–4000K 环形柔光灯，"上下半球"正好是织物网罩的两种配色。
**功能件长在造型特征上**，这是硬件设计最划算的做法。

> 尺寸改了要同步三处：PRD、三视图、BOM。本案从"⌀120×86 半球"改为
> "Φ120×126 球体（含 6mm 底座）"，PRD 里必须写清"形态变更"和原因。

### 第 2 步：选型三问（每个器件都要过）

1. **非它不可吗？**（能用软件补的，先别上硬件）
2. **它的输出是什么量？**（特征值 ≫ 原始数据，隐私与算力都友好）
3. **断了会怎样？**（离线时核心功能还能不能跑）

本案选型表（可直接当模板）：

| 器件 | 用途 | 关键理由 |
|---|---|---|
| 60GHz 毫米波雷达 | 呼吸率/体动/在离床 | 无接触、穿透被褥、**只出特征值不出点云** |
| 4 麦远场阵列 | 鼾声/环境噪音/语音 | 感知入口与交互入口二合一 |
| 温湿度 + 环境光 | 环境基线 | 便宜，支撑空调/灯联动决策 |
| RGBW 环形灯 1800–4000K | 日落/日出/呼吸引导 | 灯的"表情"就是界面（无屏产品必备） |
| 1.75" 全频 + 无源辐射器 | 夜间音景 | **限幅 65dB**，夜里不能吵 |

### 第 3 步：结构红线（写下来，做成检查项）

- 🔴 **引脚复用**：本案 PA10 同时是屏幕电源使能与功放使能。任何把它拉低的代码
  都会让屏幕掉电且无法恢复。→ 上电表必须列"一个引脚几个用途"
- 🔴 **麦克风物理断电**：拨杆机械断电，不依赖软件承诺（隐私是卖点，不是合规）
- 🔴 **无摄像头**：物理上不存在 ≠ 可以关闭
- 🔴 **夜间声压限幅**：给扬声器加硬限幅，别指望音量滑条

### 第 4 步：BOM 与成本

模板：器件 | 型号 | 数量 | 单价 | 小计 | 备注

本案：BOM ≈ 220 元（雷达 45 + 主控 NPU 60 + 其余），整机 480g，
USB-C 供电。**零售 599–799 时硬件毛利为正**，订阅才是利润。

自检：BOM 成本 × 2.5 ≈ 建议零售价。低于 2 倍，渠道和售后会吃掉全部毛利。

### 第 5 步：样机路线（别一上来打板）

```
开发板（现成屏幕/按键/麦克风/扬声器映射）
  → 飞线验证传感与音频通路
  → 3D 打印外壳验证手感与声学
  → 小批量 PCB + 结构件
```

本案用 openvela（小米 Vela 开源版）开发板：**屏幕、按键、麦克风、扬声器都是现成映射**，
所以固件层可以先跑通，再谈工业设计。

## 交付物

1. 形态方案 2–3 个（含优缺点，最好有渲图）
2. 选型表（器件 / 用途 / 理由 / 备选）
3. BOM 表（含总价与零售价建议）
4. 结构红线清单
5. 样机路线图（开发板 → 飞线 → 打印壳 → 小批）

## 反模式

- ❌ 为了"高级感"堆传感器（每个传感器都是一条要维护的代码路径）
- ❌ 造型先定死，再往里塞器件（最后一定塞不进）
- ❌ BOM 只算主料，忘了结构件、包装、售后
- ❌ 无屏产品却没设计"设备怎么表达状态"（灯效即界面）

## 验收门

- [ ] 形态能一句话说清，并且功能件长在造型特征上
- [ ] 每个器件能回答"非它不可吗"
- [ ] 引脚复用表已列全，冲突已清零
- [ ] BOM × 2.5 ≤ 建议零售价
- [ ] 夜间声压、功耗、散热三项有具体数字
- [ ] 样机路线第一步是能买到的开发板
