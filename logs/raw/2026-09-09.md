## 1. 编译固件是啥意思

打个比方：板子（SF32LB52）是一台**空电脑**，出厂时啥都不会。openvela 的源码是一堆**文字代码**，芯片看不懂文字，只能看懂机器码。

- **编译** = 把文字代码"翻译"成芯片能执行的机器码，得到一个文件（.bin/.img）。这一步只能在 Linux 电脑（Ubuntu 22.04）上做，因为 openvela 的翻译工具只认 Linux。
- **烧录** = 把翻译出来的文件"写进"板子的存储里。
- **固件** = 烧进板子里的那个系统，就是"装好系统、能跑起来的板子"。

所以「编译固件」= 在 Ubuntu 电脑上，把 openvela 代码翻译成能烧进板子的程序。这不是可选项，是要跑真机的第一步。

## 2. openvela 架构是不是必须的

**必须，而且这是大赛的硬门槛。**

这是「2026 openvela AI 硬件开发者大赛」，规则白纸黑字写了一条硬性要求：

> 项目须使用 openvela 系统能力，且至少落地图形、AI、多媒体三项核心能力之一。

不用 openvela 直接写裸机程序，技术上能跑，但**不是这个大赛的作品，直接不合格**。

于是逻辑链就锁死了：

```
大赛要求必须用 openvela  →  必须编译 openvela 固件  →  编译必须 Ubuntu 22.04  →  你得有个 Ubuntu（租云/VM）
```

也就是说：那个 Ubuntu 环境不是"我为了玩模拟器才要的"，是"只要参加这个比赛、要上真机，就绕不开"。
