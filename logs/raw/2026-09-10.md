## 本机配置 vs openvela 要求

| 项目 | 你这台机器 | openvela 要求 | 判断 |
|---|---|---|---|
| CPU | i5-8300H 4核8线程 2.3GHz | 无硬性，i5+ 即可 | 够，但编译偏慢 |
| 内存 | 16G 总，**当前仅剩 4.4G** | **至少 16G** | 卡线，编译时要关掉其他程序 |
| C盘 | 118G，**仅剩 14G** | — | 绝对不能放 C 盘 |
| N盘 | 1.4T，**剩 831G** | 源码+产物 40~150G | 放 N 盘，绰绰有余 |

## 为什么这么大（45G+）

`repo sync` 拉的不是一个内核，是**一整棵 Android 式全家桶编译树**：
- NuttX 内核 + apps + packages + vendor（所有芯片的板级包）
- **最大头是多套交叉编译工具链**——ARM Cortex-M/A、RISC-V、Xtensa 每种架构一套 GCC/clang，每套几百 MB 到 1G+
- Git LFS 二进制大文件（字体、图片、模型权重）+ 每个仓的完整 git 历史

设计成这样是因为它要"一套树编所有芯片"。你只为 SF32LB52 编，实际只用到其中一小块，但 repo 默认全拉。用 `-c --partial-clone` 能砍掉不少历史，但工具链砍不掉。

## 性能判断：本机勉强能跑，但不划算

- **编译时长**：i5-8300H 全量编 openvela，估计 **2~4 小时**（官方 1~3 小时是更好的机器）。
- **内存**：LVGL + C++ 并行编译 `-j8` 峰值吃 8~12G，你只剩 4.4G，会疯狂 swap，更慢。
- **致命点**：Windows 原生编不了，WSL 官方不支持。要么装 VM，要么上云。

**"不行就真机"这条走不通**——真机 SF32LB52 也得先编出固件才能烧，编译这步省不掉。我们是 C/LVGL 原生应用，不是快应用（快应用才能用轻量 aiot-toolkit 打 rpk）。所以**全量编译绕不开**，问题只是"在哪编"。

## 三个方案，你选一个

| 方案 | 成本 | 速度 | 适合 |
|---|---|---|---|
| **云 Ubuntu**（推荐） | 按量几块钱/小时 | 4核8G 云机 1~2h 编完，不占本机 | 想省事、不折腾 |
| **本机 VM**（VMware/Hyper-V） | 0 元 | 装 Ubuntu，虚拟盘 120G 放 N 盘，编 2~4h，内存吃紧 | 不想花钱、N盘够大 |
| 大赛官方云/AIoT-IDE | 看组委会 | 待确认是否提供 | 先去群里问小汤有没有官方云编译 |

云服务器的调试完全可行，关键是**分清三层**，每层调法不同：

## 第 1 层：核心逻辑 —— 本地调，不用云（占我们 80% 的代码）

我们的哄睡状态机、噪声生成、日程调度是平台无关 C 代码，本机 mingw gcc 就能编能跑：

- `make test` → 465 项断言
- `make app` → 整晚闭环模拟（睡前流程→入睡→夜醒→晨唤）

改逻辑、验算法，在这台 Windows 上秒级完成，跟云没关系。这层我们已经搭好了。

## 第 2 层：模拟器（openvela emulator）—— 云端跑 + 图形回传

模拟器是 Linux ELF，只能在云端跑。三种看画面的办法：

| 方式 | 怎么做 | 体验 |
|---|---|---|
| **VS Code Remote-SSH**（推荐） | 本地 VS Code 装 Remote-SSH 插件，连云服务器。代码、终端、编译、GDB 全在云端，编辑界面在本地 | 最顺手，改一行保存即在云端 |
| VNC / xrdp | 云机装桌面，本地 VNC 客户端连过去 | 能看模拟器窗口，稍卡 |
| 纯串口 `-nographic` | 不要画面，只看串口日志 | 最快，适合验状态机不验 UI |

**我们的 LVGL 呼吸动画需要看画面**，所以走 Remote-SSH + VNC 组合：VS Code 里改代码编译，VNC 里看模拟器屏。

GDB 断点调试：云端直接 `gdb` 挂模拟器进程，或 `gdbserver` + SSH 端口转发到本地。

## 第 3 层：真机 SF32LB52 —— 云端编译，本地烧录

板子插在你 Windows 上，云机看不到它（USB-over-IP 不靠谱，别折腾）。循环是：

```
云端 repo sync（一次，几小时）
   ↓
改代码 → git push → 云端 git pull → 增量编译（几十秒~3分钟）
   ↓
把 .bin/.img 从云端拉回本地（scp，几 MB，几秒）
   ↓
本地用 SiFli 烧录工具写进板子 → PuTTY 看串口日志
```

**要点：只有首次全量编译 2~4 小时，之后改我们的 app 是增量编译，1~3 分钟一轮**。这个循环完全可接受。

串口日志是最主要的真机调试手段（openvela 内核日志 + 我们 `printf` 的状态机轨迹都从这里出来），这也是评审认可的"真机证据"之一。
