# 2026-09-13 真机音频通路打通（DAC 放音 + ADC 采集）

板子到手的第二天。前一天把 AMOLED（CO5300）点亮了：
面板 ReadID=0x331100 跟预期一致、VADD_EN(PA37) 拉高、背光 ON(PA01=1)、
三种纯色 cmdtest 都过。今天专门搞音频。

## 1. 先把硬件通路摸清楚

没靠猜，对着 vendor_sifli 的板级源码和思澈 SF32LB52 的手册，
把音频相关的器件、引脚、时钟、DMA 通道列成一张对照表，再跟原理图的网络名一条条核对。

**通路是这样的**（后面所有调试都靠这张图）：

```
放音：AUDCODEC DAC1 (A.33) → NS4150B 功放 U0104 → 喇叭 J0101
      └ 功放使能脚 PA10（高有效）
采集：M0100 (WMM7037) → MIC_BIAS → AUDCODEC ADC1/ADC2
      → 数字 ADC_CH0 → DMA1_Channel4（请求号 39）
```

第一个坑是 `BSP_ENABLE_DAC2` 这个宏。一开始以为"两个 DAC 都该开"，
结果编译报错、行为也不对。核对之后发现
**`BSP_ENABLE_DAC2` 只在 LB58X 系列定义，LB52 的 DAC2 本来就是禁用的** ——
设计如此，不是缺陷。LB52 只要 DAC1（A.33）这一路，把它的输出级 `EN_OS_DAC` 打开就行。

教训：平台差异宏要用编译守卫隔开，别假设同系列芯片的寄存器集都一样。

## 2. 初始化顺序（顺序错了后面全错）

音频时钟树对顺序很敏感。实际跑通的顺序：

1. 音频时钟使能（HXT BUF_AUD + AUDCODEC 门控）
2. PLL / 数字块使能位（EN_DIG / EN_SDM / EN_CLK_DIG + 模拟偏置）
3. REFGEN（模拟参考源）使能
4. HAL_AUDCODEC_Init → Config_TChanel / Config_RChanel
5. 放音 Transmit_DMA（6400 字节 / 2×1600 采样，循环）
6. Config_Analog_DACPath
7. PA10 使能（功放 NS4150B）
8. 采集 Receive_DMA（4096 字节 / 2048 采样，循环）
9. Config_Analog_ADCPath（MICBIAS + ADC1/ADC2 加电）→ ADC 总开关

第二个坑：先开 ADC 再开 DAC，会拿到一个不稳定的 REFGEN 基线，采集噪声明显变大。
把 REFGEN 提到最前面就干净了。

## 3. 寄存器回读（不信"函数返回 0 就算成功"）

初始化完把关键寄存器打出来逐位核对：

```
[init] ID=c0dec000 CFG=0000001b PLL_STAT=00000004
[init] BG_CFG0=00001931 REFGEN_CFG=00000005 DAC_CFG=00000114
[init] DAC_CH0_CFG=029b0689 DAC1_CFG=01f78001
[init] ADC_CFG=00000a09 ADC_CH0_CFG=00010e9d ADC_ANA_CFG=0000002e
[init] 关键位: EN_DIG(b13)=1 EN_SDM(b30)=1 EN_CLK_DIG(b23)=1 EN_ANA(b15)=1
             ADC_ENABLE=1 DAC_ENABLE=1 ADC_CH0_EN=1 ADC_CH0_DMA_EN=1
[init] TX: ISR=00000000 CNDTR1=679 CCR1=00002abf CSELR1=27000029
[init] RX: CNDTR4=756 CCR4=00002aaf CPAR4=50088040 req4=39(CSELR1.b24)
[init] 计数 TX HT=3 TC=2 TE=0 | RX HT=0 TC=0
```

- `TX HT=3 TC=2`：放音 DMA 的半满/全满中断真的在跳，不是死循环
- `req4=39`：录音 DMA 请求号和手册对得上
- `TE=0`：没有传输错误

## 4. 采集链路自检：用 Goertzel 判"1 kHz 到底进没进来"

放本地 1 kHz，用 Goertzel 算法量麦克风的频谱。

- N=1024 @ 16 kHz → 15.625 Hz 一格，1 kHz 落在第 64 格（系数 60548）
- 这里有个判据要修正：**不能拿"峰值在第 64 格"当结论**，白噪声也会把某个格子顶起来。
  必须要求 **1 kHz 相对邻近频点（750 / 1250 Hz）抬升 4 倍以上**，
  才能说"这个频率真被听见了"。

板上的原语 `aud_goertzel(p, n, coef)`，单位大概是 4 LSB 幅度算 1，换算的时候别搞错。

| 功放使能脚 PA10 | 置位 |
| 喇叭到底有没有出声 | 当天不知道。单窗读数跳得太厉害，判不出来，留到第二天做对照组 |

## 记下来的几条教训

1. **"函数返回 0" 不等于 "硬件生效"** —— 关键寄存器必须回读、逐位核对。
2. **频谱判据要用相对抬升，不能用绝对峰值** —— 不然噪声也能"通过测试"。
3. **单窗频谱读数方差很大** —— 1 kHz 读数在 64 和邻近的 21~37 之间来回跳，得多窗累加才有结论。
4. 平台差异宏（`BSP_ENABLE_DAC2`）必须在编译期隔离。
