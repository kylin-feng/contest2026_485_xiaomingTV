## 4. 演示链路排雷（本轮最有含金量的修复）

### 4.1 `prototype/serve-https.py`：证书路径写死 `/tmp`，Windows 必挂

原版 `load_cert_chain('/tmp/sle-cert.pem', ...)` 是 macOS 写法，这台 Windows 决赛演示机
上启动即报错——**手机语音演示的关键路径，上场前发现就是事故**。

修复：证书路径改为脚本同目录；缺失时自动探测局域网 IP 并调 openssl 生成
（SAN 带局域网 IP + 127.0.0.1 + localhost）；加 `--cn` / `--port` 参数；
输出的访问提示带上实际 IP。

**实测**：`py serve-https.py` 首次运行自动出证书，`curl -k https://127.0.0.1:8443/m.html`
返回 200（141446B，与 HTTP 版同大小）。生成的 `sle-*.pem` 是私钥，已加 `.gitignore` 不入库。

### 4.2 ×20 演示加速：验证通过，但第一次测了个假阳性

代码事实（m.html）：连点宠物 5 下切换 `demoSpeed=1↔20`，`T = s => s*1000/demoSpeed`
统一换算，Agent 巡检（1000/demoSpeed）、渐弱、日出计时全部随之提速——路演几秒钟
演完一整晚。

第一次用合成 `pet.click()` 点 5 下没反应，差点误判功能失效；读代码发现监听的是
**pointerdown** 而非 click。改派 5 个 PointerEvent 后 toast「演示模式 ×20 已开」
正常触发。**结论：真机触控/鼠标按下有效；自动化验证要派对事件类型。**
此坑已写进演示脚本，防止后来人再测一遍假阴性。

### 6.3 新增「演示速览」（本轮主要功能）

**为什么必须做**：此前文档写的"连点宠物 5 下 = ×20 加速"，实测发现**演示中并不可用**——
`demoSpeed` 只提速计时器，而日出的触发点是真实时钟（明早 07:00），
一整夜 ÷20 仍要 54 分钟，25 秒里只能看到"清醒"。这是我自己写进演示脚本的承诺，必须能兑现。

**做法**：`demoTour()` 一条脚本化时间线，25 秒演完：
日落 → 3s 浅睡 → 7s 深睡 → 9s 噪音遮蔽 → 12s REM → 15s 深睡 → 17s 夜醒耳语
→ 20s 日出（临时 demoSpeed=10 让日出动画 1.7 秒走完）→ 27s 报告并跳报告页。
速览的报告用 `session.demo` 标记按一整夜出数（7h12m / 深睡 31%），
避免 25 秒演出被算成"3 分钟睡眠"。中途再连点 5 下退出，退出不生成报告。

**实测**：评分 90 / 总时长 7h12m / 深睡 31% / 夜醒 1 / 遮蔽 1；
结束后三个遮罩都是 0、按钮复位「开始晚安」、不重复计夜。

## 7. 再一轮：速览夜景修复 + 补齐未测功能 + 当天清单

### 7.1 速览的夜景问题（观感，不是崩溃）

第一版速览直接调 `sunset()`，而真实日落是 8 分钟渐暗——25 秒的速览里它永远走不完，
于是演到「深睡」时屏幕还蒙着落日橘色、宠物也没睡下，**夜景根本进不来**。
抽帧看视频才发现（截图比读代码更容易发现这类问题）。

修法：速览内单独走一条 3 秒日落（然后进夜色）；中途试过 `ovDark=1`，结果整屏纯黑
（真实流程里整夜就是纯黑熄屏，这是设计），速览改用 `.42` 压暗——评委看得见阶段在变，
又保留"夜里屏幕不亮"的语义。重录视频，终版 43.9 秒，含报告收尾。

### 7.2 录制踩坑两条（写给以后）

- Playwright 按选择器点宠物会报 `click actionability (not-stable)`——宠物有上下浮动动画，
  元素永远"不稳定"，录制直接失败。改用**坐标点击**。
- 连点必须**恰好 5 次**：4 次不触发，第 5 次才越过阈值。第一次录完发现只有 4 次，
  录出来是一段 40 秒的静止主控页。教训：录制脚本要像测试一样断言结果，别只看 status=completed。
