# AI Coding 日志

这里记的是这个作品在 AI 辅助下真实的开发过程，给大赛的「AI 开发」这一项做核验用。

## 怎么记的（如实说明）

- 工具是 WorkBuddy / AI Coding Agent（09-08 ~ 09-15）和 Kimi Code（09-16 起），
  都是会话式协作，不是那种逐字存 prompt 的工具。
- 所以这里的内容是**按模块归档的协作记录**：每条写清楚日期、做了什么、
  AI 帮了哪部分、自己定了什么、最后产出和验证结果。
- 里面写的「AI 帮了什么」是对当次指令的**摘要**，不是逐字原文。
  但**代码、日志、测试结果都是仓库里的真实文件**，
  可以对着 `src/`、`tests/`、`docs/测试记录表.md`、`docs/真机运行证据_20260914.md` 核验。
- 原始对话也导出了一份，在 `logs/raw/`，一天一个文件（2026-09-08 ~ 09-19，共十天，
  115 轮用户指令），是从两个工具的会话暂存里逐条导的原文 ——
  两边的暂存都只存在本机、不会自动进仓，得主动导出（09-16 之后那几天用的导出脚本
  `tools/export_ai_logs.py` 已入库，可复现）。
  用户指令和助手回复基本整段保留，工具调用留参数摘要、工具结果每条留 1000 字以内，
  模型思考只留节选；里面的 GitHub 令牌、API key、云机密码都替换成了 `<已脱敏>`。
  09-04 和 09-06 本机没留下会话记录，09-13 有摘要但找不到对应原始对话，**这两处对不上是实情**，
  具体见 `logs/raw/README.md`。

## 一句话总结

7 个 C 模块、6 组单元测试、465 条断言。做法都是 AI 出骨架，
算法的判据和边界条件由人来定，每个模块都走一遍
「生成 → 人工审读改 → 编译 → 跑断言 → 再改」。
另外有 HAL 双后端（sim / sf32lb52）和 openvela 的主循环（`app/mianyu/`），
评审 clone 下来 `make test`（465 断言）、`make app`（整晚闭环）就能自己验一遍。

真机侧（SF32LB52-DevKit-LCD）的过程在 `docs/真机运行证据_20260914.md`，
包括符号核验、启动日志、链路丢帧统计、声学回环对照。
里面有项没通过的也照实写着：喇叭本体没出声，得人确认一下 J0101 插没插喇叭。
