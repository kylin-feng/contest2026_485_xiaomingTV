# 界面层（openvela / LVGL 9）

这一层只在 openvela 工程里编译（`#include <lvgl/lvgl.h>`），PC 侧不参与 ——
PC 的 `make app` 走的是 `hal/sim`，那条路上界面接口全是空实现，见
`hal/sim/mianyu_hal_sim.c` 里"手表界面"那一段。

| 文件 | 里面是什么 |
|---|---|
| `watch_ui.c` / `.h` | **手表界面**：表盘页 + 哄睡页，两页切换、触摸交互、状态刷新，以及**语音状态显示**（空闲/在听/在想/在说，小圆点跟着状态呼吸） |
| `breathe_lvgl.c` / `.h` | 最早那版只有一个呼吸光晕的渲染壳。现在由 `watch_ui.c` 接管，**不参与编译**，留作移植过程存档 |
| `lv_font_mianyu_16.c` / `_32.c` | 界面用的中文字体，只含界面上出现过的字。**字符集由 `tools/gen_mianyu_fonts.py` 从 `watch_ui.c` 里扫出来**，不要手工维护 |

编译清单见 `app/mianyu/CMakeLists.txt`（那边只挂 `watch_ui.c` + 两个字体文件）。

## 语音状态怎么显示出来的

屏幕上那行「● 在听」不是板子自己猜的。板子只看得到串口上有没有音频在流，
分不出是**用户**在说还是 **AI** 在说（两者都是音频），更看不到"模型正在算"
（那段时间串口上一个字节都不动）。

所以状态由 **PC 侧网关**判定并下发：

```
网关判定（voice/gateway.py: _ui_state_code） ── CMD_UI_STATE(0x0B) ──▶ 板子 g_ui_state
                                                                        ──▶ 主循环 my_hal_voice_state()
                                                                        ──▶ 快照 st.voice ──▶ 界面
```

优先级与理由：

| 值 | 屏幕 | 判据 | 为什么是这个优先级 |
|---|---|---|---|
| 3 | 在说 | `state == SPEAKING` | 喇叭在响时必须说"在说"，否则用户会以为它在听、对着它说话，结果被自己的声音顶掉 |
| 1 | 在听 | `vad.active` | 用户正在说话，这是当下最该显示的事实。**不能用 `state == LISTENING`** —— 服务端会一直续着会话，那个条件几乎恒为真，屏上会永远显示"在听"，等于没有信息 |
| 2 | 在想 | 整句已送出、在等结果 | 四态里唯一串口上看不出来的一个，只有网关知道 |
| 0 | 空闲 | 以上都不成立 | 表盘静止，不产生持续重绘 |

网关侧带两道兜底：状态**变化时**才发 + 每 3 秒重发一次（CMD 帧混在音频流里
有极小概率丢，丢了屏幕会永远停在错的状态）；"在想"另加 15 秒超时，
免得服务器不回时屏幕一直卡着。

## 为什么不用 LVGL 自带的字体

LVGL 内置的 `lv_font_montserrat_*` **不含 CJK 字形**。界面上的
「吸气 / 屏息 / 呼气 / 开始哄睡 / 昨晚睡了 7 小时 21 分」全是中文，
用 montserrat 只会得到一串方块。

所以从文泉驿微米黑（`wqy-microhei.ttc`，GPL v2 + 字体例外）抽字形，
按界面实际用到的字集合裁剪。**只裁用到的字**，所以体积很小：
16px 约 92KB，32px 约 269KB（源码文本，编进固件的是压缩后的点阵）。

## 怎么重新生成

**不要再手写字符清单了。** 上一版是手工维护一串 `--symbols`，结果界面文案
改过之后字体没跟上，屏上出现了 12 个方块（「周二」的"二"、「放松」的"松"、
「呼气」的"呼"、"还没有记录"整句 ……），而且不报任何错。手工抄字符集这件事
本身就会漏，所以现在改成**从界面源码里抠字**：

```bash
# 只需要一个中文字体源和一个 lv_font_conv
npm i lv_font_conv                     # 或装在项目内，用 LV_FONT_CONV 指过去

python tools/gen_mianyu_fonts.py --check   # 先看会收进来哪些字
python tools/gen_mianyu_fonts.py           # 生成 ui/lv_font_mianyu_{16,32}.c
```

脚本做的事：把 `ui/watch_ui.c` 里所有字符串字面量的非 ASCII 字符扫出来取并集，
再用它作为 `--symbols` 生成两个字号。**以后改界面文案，重跑一次这个脚本就行，
不会再漏字。**

字体源按顺序找（见脚本里的 `FONT_CANDIDATES`）：
`$MIANYU_FONT` → `/tmp/wqy-microhei-0.ttf` → `C:/Windows/Fonts/NotoSansSC-VF.ttf`
→ `C:/Windows/Fonts/simhei.ttf` → 系统里的文泉驿。
**注意不支持 TTC**：把 `msyh.ttc` / `simsun.ttc` 传进去会报
`Unsupported OpenType signature ttcf`，所以候选里只放单体 TTF。
当前用的是 **Noto Sans SC**（可变字体，默认字重渲染正常，已验证汉字点阵非空）。

本轮收进来的 93 个非 ASCII 字符（脚本会打印同一份）：

```
·一三中了二五今你光入六几分到刷动听吸周呼哄噪四回在夜好始安定小就屏已幕开弃录待息想抚按接放新日时昨晚月有机束松棕次正气没活点用界白的盘着睡秒粉结继绪续自表记说跟返还醒量长面音页（），：
```

（其中「刷幕弃按束活界盘结继续长页」这些来自 `syslog` 日志文案而非屏幕文案 ——
多收几个字只是字重多几 KB，不影响正确性，所以没有为它做区分。）

ASCII 段是 `--range 0x20-0x7e`：时间「22:30」、百分比、半角标点都在里面。
**中文标点不在里面**，要用得让它出现在某个字面量里才会被收进去
（当前收到了全角 `（），：` 四个）。

生成的文件第 4 行是本次使用的完整参数，可以直接和脚本行为比对。

### 字号怎么定的

| 字号 | 用在哪 |
|---|---|
| 32px | 表盘上的大时间、哄睡页的阶段文字（「吸气」「屏息」）—— 这两处是躺着也要能看清的 |
| 16px | 日期、语音状态、计划、昨晚简报、噪声类型、已用时 —— 都是次要信息 |

最小 16 是有意的下限：再小在 390×450 的屏上就要凑近了看，而这块屏是在床头、
半睡半醒的状态下扫一眼的。
