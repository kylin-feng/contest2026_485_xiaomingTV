# 评委答辩预案（20 问）

用法：每题先背**一句话结论**，再看证据。被追问细节时只答证据那一段，不要主动扩写。
带「如实」标记的，是必须承认的边界——评委最反感的是把模拟说成实测。

---

## A. 技术与产品（1-8）

**1. 为什么做成复古掌机？不奇怪吗？**
一句话：现实世界里它是床头的一轮"小月亮"（半球形设备），掌机是**软件原型的形态**——
用最直观的实体感展示"设备本体就是这个宠物"，同时让评委在手机上就能体验完整交互。
证据：PRD 第 5.1 节定义了 ⌀120×86mm 硬件；原型用掌机壳承载同一套 Agent。
（如实）原型不等于最终工业设计，硬件形态以 PRD 为准。

**2. 为什么不做手机 App？大家都有手机。**
一句话：因为手机上本来就有那个让人睡不着的东西。
证据：睡前交互全部在设备上完成（语音 + 顶部触控），App 只用于白天看报告；
README 第一性原理那段——黑暗中不按按钮、不睁眼看屏幕。手机 App 一打开，
通知、短视频、工作消息全回来了，这是产品定位问题不是功能问题。

**3. 睡眠分期是模拟的，凭什么说有效？**
一句话：分期在原型里是模拟的，但**固件侧的判定算法是真跑过的**，且我们从不混着说。
证据：`app/mianyu` 里入睡判定用时域 RMS 包络 + 归一化自相关，465 条断言全绿，
混淆矩阵 TP38/FN0/FP0/TN81（**合成信号**）；真人整夜标定还没做，报告里标了。
（如实）接真硬件是单点替换 `sim.stage`，不动上层 Agent 逻辑。

**4. Agent 和 LLM 是什么关系？没有大模型是不是就废了？**
一句话：Agent 是决策主体，LLM 只是"嘴"，两者解耦。
证据：V1 规则引擎 60+ 条（噪音遮蔽、鼾声掩蔽、体动闪避、阶段换挡、渐弱计划）
在端侧跑，断网可用；LLM 负责自由聊天，key 只存本机，没 key 时用内置温柔应答兜底。
路线是 V1 规则 → V2 端侧小模型 → V3 云端大模型生成个性化话术。

**5. 小米音箱几十块就能放白噪音，你凭什么卖 799？**
一句话：白噪音机不知道你什么时候睡着，也不知道雷声来了要推遮蔽层。
证据：六条核心规则（R1-R5+鼾声）是"看状态做动作"，不是定时器；
而且它指挥全屋（米家灯/帘/空调），音箱只管自己一个喇叭。

**6. 五层音景实时合成，用户能听出区别吗？**
一句话：听不出"五层"，但听得出"不重复、不突兀"。
证据：底噪/场景/遮蔽/点缀/晨鸟五层独立控制，点缀层随机永不重复（录音循环会露馅）；
入睡后渐弱用等功率曲线（人耳听感匀速），末段线性归零，中途闪避不反弹。
工程收益：Flash 占用 0KB，16MB 闪存本来也存不下几条无损音频。

**7. 断网了还能用吗？**
一句话：核心功能全本地，只有自由聊天需要网。
证据：音景合成、分期、光引导、闹钟、养成全在端侧；LLM 对话是可选增强。
PRD 第 6.3 节异常路径：网络中断时米家联动降级为本机动作。

**8. 卧室放个带麦克风的设备，用户不害怕吗？**
一句话：隐私不是合规成本，是营销资产——"数据不出卧室"印在包装盒上。
证据：无摄像头（物理不存在，不是"可以关"）；麦克风机械断电拨杆；
雷达只输出呼吸率/体动特征值，原始点云端侧销毁；整夜决策全端侧，
云端只同步匿名周报且可一键关闭。

## B. 商业（9-14）

**9. 599-799 是怎么定的？**
一句话：参照 Hatch ≈170 美元（约 1200 元）与 Sleepal 449 美元，我们做"普惠中枢"。
证据：BOM ≈220 元（雷达 45 + NPU 60 + 其余），硬件毛利为正；
比 Hatch 便宜近一半，但多了全屋编排和对话能力。

**10. 用户凭什么每月付 15 块？**
一句话：付费点不是"功能锁"，是持续更新的内容与越来越懂你的建议。
证据：每周新音景配方（雪夜木屋、江南梅雨…）、被动学习内容库（家长刚需）、
记忆层个性化结论（"海浪让你平均快 6 分钟入睡"）。
行业参照：Oura 会员一年留存 85%，Hatch 内容订阅约 300 万美元/月。

**11. 小米自己做了怎么办？**
一句话：我们做的是米家缺的那层"编排协议"，被收购也值；大厂做要协调跨品类利益，慢。
证据：生态位地图——床垫 8H、感知 Sleepal、穿戴 Oura 各自为战，编排层空白。
先发优势在编排协议和用户睡眠记忆数据，这两样越用越厚。

**12. Hatch 已经两亿美金了，你怎么跟它打？**
一句话：它只管自己一台设备，我们指挥用户家里已有的设备——这是两条不同的赛道。
证据：Hatch 无感知、无联动、无对话；我们从感知到执行闭环。
在中国市场它没有米家生态入口，价格也高一倍。

**13. 获客成本算过吗？**
一句话：没有投放过，不做承诺；早期靠内容与场景自然传播。
证据（如实）：目前没有任何获客数据。设计上的低成本路径是"爸妈的睡眠报告"
可转发（PRD 5.5.3 节，微信小程序形态），被动学习内容是家长群天然话题。
（这类问题不编数字，评委会更信任"我们还没验证"。）

**14. 为什么 B 端是二期，不是一开始就做？**
一句话：B 端要可靠性背书，C 端要口碑，顺序不能反。
证据：Sleepace 走养老院/酒店按床位付费已验证可行，但要求稳定与售后体系；
先 C 端把产品磨出来，B 端作为订阅不及预期时的风险预案。

## C. 执行（15-17）

**15. 现在到底做到什么程度？Demo 是真的吗？**
一句话：软件原型 v1.8 全功能可跑，固件已在目标板跑通主链路；现场可以真机演示。
证据：原型单文件零依赖、18 个版本迭代、真 TTS/真语音识别/Web Audio 合成；
固件 465 断言全绿、串口语音 20 秒零丢帧、屏幕触摸在板上验证通过。
（如实）喇叭没出声是**缺件**（板上喇叭座是空的），不是软件问题；
屏幕肉眼确认这一项当时没做，方法写在仓库文档里。

**16. 硬件什么时候能出来？**
一句话：软件已经验证完，硬件是把已验证的模块搬上 openvela 开发板，不是从零开始。
证据：路线图四步——软件验证（已完成）→ 硬件迁移（屏幕/按键/麦克风/扬声器现成映射）
→ 感知升级（雷达单点替换）→ 商业化。

**17. 团队怎么分工？凭什么是你们？**
一句话：（现场按真实情况回答，PPT 团队页有占位待填）
证据提示：产品+Agent 一人做过 18 个版本的原型；硬件一人搞定 openvela 板级 bring-up
（36 版调试流水全在仓库里，失败版本也留着）；内容+运营一人负责配方与订阅内容。

## D. 刁钻问题（18-20）

**18. 加上宠物，会不会变成玩具，削弱专业性？**
一句话：宠物不是装饰，它是让用户"愿意每天回来"的那层，也是夜醒时有人回应的那层。
证据：哄睡本质是情绪问题（第一性原理）；夜醒时耳语"我在，别急着看手机"
比任何数据都管用；而且金币经济把"按时睡觉"变成了有回报的行为。
（如实）"宠物是否显著提升留存"目前是假设，靠真机试用一周验证——
北极星指标仍是入睡潜伏期 4 周缩短 20%。

**19. 陪孩子睡模式，会不会让孩子对设备上瘾、反而睡不好？**
一句话：这个模式的设计全部朝向"降低刺激"：无屏幕、无游戏化提示音、到点课本被没收。
证据：产品三不做（不做屏幕/不做摄像头/不做单品）；睡前学习是**被动磨耳朵**
（轻声读弱词+古诗），不是让孩子做题；过睡觉点主动收课本。
（如实）儿童场景的有效性与安全性需要专门评估，我们不做医疗宣称。

**20. 数据都在端侧，你怎么迭代算法？**
一句话：端侧出特征值、云端只收匿名统计，迭代靠**规则和话术**而不是拿原始数据。
证据：每轮闭环的决策日志（触发什么规则、执行什么动作）可匿名上报计数；
A/B 微调（雨声 vs 海浪）在端侧完成，只把"哪种更快"的结论留下。
（如实）这确实限制了模型训练的数据量，是隐私与能力的主动取舍。
