# 版本迭代日记

按固件版本顺序记的调试流水。**没通过的版本也留着，不删。**

每一条写三件事：这一版改了什么、跑出来什么、卡在哪。数字和日志原文都是从串口抓的，
不是事后回忆。固件本体在 `Desktop/mianyu-fw/`，文件名就是版本号（`nuttx_*.bin`）。

一共 36 版。其中**真正跑通的只有 6 版**，剩下 30 版都是失败的中间态。
写这份东西的用处很实际：下次板子不动的时候，先来这里看看"是不是又踩了同一颗雷"。

| 阶段 | 版本区间 | 结果 |
|---|---|---|
| 把屏弄亮 | v1 – v9（09-14 白天） | 9 版，屏黑问题最终被推翻（不是故障） |
| 音频 bring-up | v10 – v21（09-14 晚上） | 12 版，v21 才真的出声 |
| 手表界面 | v22 – v36（09-15 上午） | 15 版，v36 才是产品态 |
| **总计** | **36 版** | **跑通 6 版，失败 30 版** |

## 09-14 白天：先把屏弄亮（v1 – v9）

### v1 `nuttx.bin` · 14:25 · 1577000 B · `75f89a9478…`

第一版能烧进板子的固件。`ninja` 全绿，烧完串口有完整启动日志，**屏全黑、触摸没反应**。

当时的判断：硬件问题。事后看这个判断错了，但错得有价值 —— 后面九版都在纠正它。

### v2 `nuttx_new.bin` · 16:04 · 1577404 B · `34ed29d805…`

改了三处板级缺陷，都是照着别的板子抄错的：

1. **PA37 被抢成 I2C1_SCL** —— 但 PA37 在本板是 `LCD_VADD_EN`（CO5300 AMOLED 的 VADD 使能）。
   被改成 I2C 以后屏直接断电。改回 PA30。
2. **背光/面板供电 PA01 从来没被驱动过** —— `BSP_PIN_LCD()` 把它复用成 `GPTIM1_CH4`，
   但全树没有任何代码启动这个 PWM。在 `BSP_LCD_PowerUp()` 里改成普通 GPIO 输出高。
3. **PA30/PA31 被 LSM6DS3 胶水代码抢占** —— 本板 PA30=触摸 SCL、PA31=触摸 IRQ，
   被传感器代码拿去当 LDO 使能和 INT。删掉那两行。

**结果：还是全黑。**

### v3 `nuttx_v3.bin` · 16:16 · 1577372 B · `982d10abca…`

继续查，抓出了两条"铁证"：

```
[co5300][diag] panel ReadID=0x0 expected 0x331100 (MISMATCH)
ERROR: ft6146_touch_initialize failed: -5
```

面板 QSPI ReadID 读回 0、触摸 I2C 全总线无应答。**判定：22pin FPC 排线没插实，硬件问题。**

这条结论后来被逐条推翻了，是这一整段里最贵的一个错误。见 v4。

### v4 `nuttx_diag.bin` · 17:08 · 1611268 B · `32213e919a…`

上一版的三个"铁证"重新过了一遍，**一条都站不住**：

1. **`-5` 不是 I2C 失败。** `ft6146_hw_init()` 每步失败都调 `ierr()`，但 `ierr` 在
   `CONFIG_DEBUG_INPUT_ERROR` 没开的时候**展开成空** —— 内层日志根本印不出来，只剩外层 `-5`。
   而 `sifli_gpio_config()` 源码里**只有 `return OK`，没有错误分支**，负错误码不可能来自它。
   真正确定的 bug：`CONFIG_TOUCH_IRQ_PIN=41` 是从黄山派抄的（黄山派 CTP_INT 确实是 PA41），
   本板是 **PA31**。
2. **`i2c dev 0 0x7f` 全空是无效测试** —— 这条命令只探 0x7f 这一个地址，而且 0x7f 超出
   `CONFIG_I2CTOOL_MAXADDR=0x77`，必然全空。拿它当"总线死了"的证据是错的。
3. **`ReadID=0x0` 不能判决硬件坏** —— 驱动注释自己写着部分 QSPI 面板 ID 读取不可靠，
   而且 `find_right_driver` 有 fallback 分支。

这一版的做法：**先把判据本身弄可信，再用判据定位**。给驱动加常开 `syslog(LOG_ERR)`、
扫 I2C 全地址 0x08~0x77、PA01 上电后闪 3 次（各 300ms，肉眼就能分辨"背光通路死"
和"背光好但屏不显示"）。

补丁：`patch_diag.py`，8 处改动，幂等、自动备份 `.diag.<时间戳>`。

### v5 `nuttx_disp.bin` · 17:19 · 1612420 B · `4e660fc3fb…`

两个动作：

### v6 `nuttx_amoled.bin` · 17:24 · 1612840 B · `617d509198…`

认知翻转的一版：读了用户发的实物照片，转接板丝印写着
**`1.85inch AMOLED Module 390x450 PinP`** —— 面板是 AMOLED，不是 TFT。

然后回头读驱动才明白：**`LCD_Drv_Init()` 全程只写命令，一个像素都不往 GRAM 写**，

**没有背光 LED，闪背光不会有任何视觉反馈**。

### v12 `nuttx_audio3.bin` · 19:40 · 1623512 B · `731d753eb0…`

**这一版找到了根因。** 漏的是 Zephyr `pll_turn_on()` 里的一组数字块使能位：

```c
PLL_CFG0 |= EN_IARY | EN_VCO | EN_ANA;  ICP_SEL = 8   // 模拟偏置
PLL_CFG2 |= EN_DIG;      // bit13  数字时钟总开关   <=== 漏的就是这一位
PLL_CFG3 |= EN_SDM;      // bit30
PLL_CFG4 |= EN_CLK_DIG;  // bit23
HAL_Delay_us(50);
HAL_AUCODEC_Refgen_Init();
```

关键认知：**走 XTAL（`clk_src_sel=0`）不等于"PLL 寄存器不用管"**。Zephyr 在
`CODEC_CLK_USING_PLL=0` 时**照样**写这组寄存器，只是不做频率校准（校准只服务 44.1k 系列）。

补上之后：

```
[audio] 关键位: EN_DIG(CFG2.b13)=1 EN_SDM(CFG3.b30)=1 EN_CLK_DIG(CFG4.b23)=1 EN_ANA(CFG0.b15)=1
[audio] [init] CNDTR1=1348      →   [1s] CNDTR1=1233      ← 终于动了
```

**顺带揪出一个自己的探针 bug**：上一版读的是 `NVIC irq66 en=0 pend=0`，看着像中断没使能。
其实 NuttX IRQ = 硬件 IRQn + 16，**读 NVIC ISER 要用硬件号 50，不是 66**。
写错号得出的"中断没开"是假象 —— 这一版改成 `NVIC hwirq50 en=1`，确认中断一直是好的。

### 喇叭那件事（同一天晚上）

用**声学回环对照法**判断喇叭到底有没有出声：放本地 1 kHz，量麦克风收到的能量，
B 组功放开、C 组功放关，各叠 12 窗：

```
B 组 1kHz = 73.5     C 组 = 88.5     → B/C = 0.83
```

把功放关掉读数**反而更高** → 麦克风里那点 1 kHz 是 **DAC 输出结点串到 MIC 的板内电耦合**，
喇叭没出声。

最后看主板照片确认了原因：`SPK` 丝印旁那个白色 2pin 座 **J0101 是空的，出厂没插喇叭**。
软件全对，纯粹是硬件缺件。

### v33 `nuttx_bench.bin` · 13:00 · 1662752 B · `e95481a1d3…` · **转折**

挂上 `LV_EVENT_INVALIDATE_AREA` 回调累计脏区 + flush 探针，一次量清楚。
这一版的日志里能看到数字一路往下掉：

```
[mianyu][tmp] 5s 内 1 帧,   平均 523 ms/帧, 脏区 275788 px/帧
[mianyu][tmp] 5s 内 28 帧,  平均 150 ms/帧, 脏区 44736 px/帧
[mianyu][tmp] 5s 内 91 帧,  平均 15 ms/帧,  脏区 4954 px/帧, idle=31
[mianyu] 触摸已补挂 indev=0x200444f0
```

**根因**：`lv_label_set_text()` 是**无条件** `lv_obj_invalidate()` 的，
而且每次都 free 掉旧文本缓冲再 malloc 一个新的 —— **哪怕传进去的字符串和上次一模一样**。
主循环 10Hz 推快照，界面 10Hz 刷新，每次把时间、日期、计划、昨晚结果、阶段、噪声类型、
已用时…… **全套 8 个标签**重设一遍文字。于是每帧全屏重画，还顺带 8 次 malloc/free。

修法是加一层"值没变就一个 LVGL 调用都不发"的缓存，另配三件事：
每个标签配一个缓存字段；光晕透明度量化（外圈 16 档、中圈 8 档、内核 1 档，
避免每帧差 0.3 也标脏）；按钮文字和描边色只在 `running` 翻转时改。

**触摸的根因也在这一版定下来**：不是驱动问题，是**注册时序**。

```
t=15.26s  LVGL: lcd /dev/lcd0 open success
t=23.10s  ft6146: touch_register ret=0      ← 触摸节点这时候才出现
```

LVGL 15 秒起来，FT6146 23 秒才把 `/dev/input0` 注册出来，**中间差 8 秒**。
原来的写法是"启动时等 5 秒，等不到就永远没有触摸" —— 一次性判定必然错。
改成运行期每 500ms 探一次节点，出现就 `lv_nuttx_touchscreen_create()` 补挂。

### v34 `nuttx_bench.bin` 之后的那个坑：触摸 110 秒才挂上

补挂逻辑第一版写成 `since_probe += lv_timer_handler()`，结果**触摸 110 秒才挂上**。

原因：`lv_timer_handler()` 的返回值是**"建议下次被调用的间隔"**，也就是这一帧渲染花了多久 ——
这块屏一帧一百多毫秒的时候它就是 100 量级。拿它当毫秒累加，等于把"每 0.5 秒探一次"

## 还在的、没修的

诚实记下来，不藏：

### 1. 每版都印的两行传感器 ERROR

从 v10 起，**每一版固件**都有这两行：

```
ERROR: LSM6DS3 register failed on I2C1: -5
ERROR: sf32lb52_lsm6ds3_initialize failed: -5
```

I2C1 上这颗六轴没有应答 —— 配置是从别的板子抄过来的，本板没接这颗芯片。
不影响音频和界面，但一直没从 defconfig 里关掉，属于待清理项。

### 2. `lcd_visual task_create failed: 0`

v27 – v32 每版都出现。`task_create` **返回值是 0，也就是成功**，却被板级按 ERROR 打出来 ——
这句日志本身的措辞有问题，不是真失败。容易误导人，没去动它。

### 3. `[co5300][readback] … NO MATCH`

```
[co5300][readback] GRAM(0x2E)=7f 00 00 7f -> NO MATCH -> pixel data is not landing (QSPI write/mode)
```

板级 co5300 自检里"写 GRAM 再读回来比对"那一步对不上。**这条在 09-13 到 09-15
每一版固件里都有**，不是哪一版改出来的。

它有两种解释，日志本身分不出来：

- 坏解释：QSPI 写像素真的没落进面板 GRAM，屏上是空白或花的。
- 大概率解释：CO5300 走 QSPI 时 GRAM 读回本来就不受支持，读回来的是哑数据，这条自检是**假警报**。
  同一个 log 里 `[co5300][probe] ID len1=0x33 len2=0x3311 len3=0x331100 len4=0x33110000` ——
  同一个 ID 在 4 个字节偏移上错位重复，正是"读通路有位移"的典型样子。

**不打算靠猜把这条写成"屏是好的"。** 要人工看一眼，方法很简单：
上电重启，开机瞬间应该有纯色闪过（`[co5300][cmdtest]` 那步在刷全白 → 全红 → 全绿 → 全蓝），
跟着背光 PA01 亮灭三次。**看得到闪色，就说明像素通路是通的**，这条 readback 就是假警报。

### 4. 屏幕肉眼确认

串口能证明对象建好、渲染循环健康、触摸挂上，**证明不了"眼睛看到的是对的那一幅画"**。
这一条留给人工看板。

## 从这 36 版里能提炼出来的东西

按"下次能省多少时间"排：

1. **判据本身要先可信，再用判据定位。** v1–v3 三轮全废在"屏黑 = 故障"这个无效判据上，
   真相是 `LCD_Drv_Init()` 本来就不写 GRAM、屏黑是预期状态。
2. **所有工具都报成功，不等于功能在。** v18 那个符号抢占：`ninja` 全绿、退出码 0、
   静态库也在，但 app 整库被链接器丢掉。**改 init 入口后必须用 `nm` + 固件体积交叉验证一次。**
3. **后到设备不能一次性判定。** FT6146 比 LVGL 晚 8 秒注册，等 5 秒必然失败。
   设备节点要用运行期探测补挂，不是启动时等一个固定时长。
4. **`ierr()` 默认是空的。** `CONFIG_DEBUG_INPUT_ERROR` 没开的时候它展开成 nothing，
   "只有外层错误码、没有内层日志"是正常现象，别据此推断失败位置 —— 要定位就自己加常开 `syslog`。
5. **量出瓶颈在哪，别猜。** v28–v32 五版白干，就是因为没量。v33 一挂探针就看见了：
   flush 只花 6µs，脏区却是 66432 像素/帧。
6. **定时不要拿渲染耗时当时间。** `lv_timer_handler()` 返回值是帧耗时，
   只有 `lv_tick_get()` 是真实毫秒。踩这个坑让触摸晚了 110 秒才挂上。
7. **本板 tick 是 10ms**（`CONFIG_USEC_PER_TICK=10000`）。`usleep(5000)` 会被向上取整成 10ms，
   把节拍拉慢一倍。板级代码里做定时读 `clock_systime_ticks()` 累计，别用小值 `usleep`。
8. **改 `defconfig` 对 `ninja` 增量编译无效。** `include/nuttx/config.h` 只在 cmake configure
   阶段由 mkconfig 重生成。想让某个 `CONFIG_*` 生效又不想重跑 configure，就在源码里覆盖：

   ```c
   #undef CONFIG_TOUCH_IRQ_PIN
   #define CONFIG_TOUCH_IRQ_PIN 31
   ```
