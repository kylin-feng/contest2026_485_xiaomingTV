# SF32LB52-DevKit-LCD 黑屏：软件侧取证结论（v46–v50）

固件：`nuttx_v50.bin`（md5 `ef876a2acaeefc6be5b6cca5d09839af`，1675960 B）
日志：`cap_v50.log` / `cap_v50.raw`（另存 v46–v49 同格式日志）
烧录：本机 COM6 @ 0x12010000，与云机无关

---

## 一、结论

**面板的数字侧完全正常，但零发光。故障在模组的发光/模拟供电侧，寄存器改不出来。**

软件侧能做的都做完了：命令通路、配置通路、三路上电使能、上电时序、像素通路、
甚至连面板自己的自诊断都通过了 —— 屏幕依然全黑。

---

## 二、逐项实测判据（全部为本机 COM6 实机抓取，非推断）

| 检查项 | 实测值 | 含义 |
|---|---|---|
| ReadID (04h) | `0x331100` 匹配 | QSPI 命令通路正常 |
| COLMOD (3Ah←55h) / 回读 (0Ch) | `0x55` / `0x55` | 配置写入确实生效 |
| RDDPM (0Ah) | `0x9C` = BSTON+SLPOUT+NORON+DISPON 全 1 | 升压开、已唤醒、正常模式、显示开 |
| RDDSC (0Fh) 自诊断 | `0xC0`，checksum_comp=0 | **面板自检通过** |
| RDDIM (0Dh) 在 0x23 期间 | `0x10` ⇒ ALLPON=1 | **面板确实接收并锁存"全像素点亮"** |
| LCDC 心跳 | done==wrram、timeout=0 | 每一帧像素都推出去了 |
| PA10 / PA37 / PA01 回读 | `1` / `1` / `1`，且 PA37 可 0→1 跟随 | 三路使能真的在高，引脚真的受控 |

## 三、被实测否定的假设（不必再试）

| 假设 | 否定它的实测 |
|---|---|
| 背光/使能没拉起来 | PA10、PA37、PA01 回读全 1；PWM `PWMIOC_START -> 0` |
| 面板停在 Sleep-In | RDDPM D4=1 是 **Sleep Out（已唤醒）** |
| 写命令不生效 | 3Ah/0Ch 读写一致；且 RDDPM/0Dh 都能被命令改状态 |
| 像素数据不落地 | done==wrram、timeout==0，MB 级帧已推出 |
| 全部像素点亮命令没被执行 | RDDIM D4=ALLPON 在 0x23 期间为 1 |
| 亮度寄存器被 UCS 锁住 | 按 datasheet 走 `FE=0x80 / F4=0x00 / F5=0x00` 解锁后，`52h` 仍恒 `0x00` |
| 走 HBM 高亮通路 | `66h=0x01` + `63h=0xFF` 后 `64h` 仍恒 `0x00` |
| 上电时序 / VCOM 极性 | 冷上电重做 + `INVON/INVOFF` 交替 6×8s，全程全黑 |

## 四、下一步（硬件侧，本机万用表就能做，不需要云机）

1. **量模组 FPC 电压**：跑着 v50（所有使能保持高）时量
   `VCI(3.3V)`、`VDDI(1.8V)`、`AVDD/VADD`、`ELVDD/VPP`、`VCL/VSN(负压)`。
   CO5300 的 BSTON 虽报 1，但升压要外部电感/电容才成立，输出为 0 就是这个症状。

2. **重点确认 PA01 的真实身份**：同一份 SDK 里另外两块 CO5300 板
   `lckfb_huangshan_pi` 和 `sf32lb52_lchspi_ulp` 都把 `LCD_VADD_EN` 定义成 **PA01**；
   只有 devkit_lcd 用 PA37，并把 PA01 叫 "BL PWM"。
   **AMOLED 没有背光**，所以 PA01 极可能就是模组的 EL/VADD 使能脚。两个脚都要量。

3. **交叉验证屏坏还是板坏**：把这屏接到黄山派（同芯片、同 `co5300.c` 驱动）跑一次。
   亮 = devkit 的 LCD 供电电路问题；不亮 = 模组/FPC 问题。
