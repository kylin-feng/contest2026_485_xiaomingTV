# 真机跑起来是什么样（2026-09-14）

固件：`nuttx_audio12.bin`，1639192 字节，烧在 `0x12010000`。
串口：COM6，1000000 波特（UART1 = /dev/console）。
原始日志：`logs/bootlog_app_v12.txt`。

这一篇只写能复现、能核对的东西。每条都写清楚是怎么看出来的。

---

## 先说结论

哄睡 app（7 个核心模块 + HAL 双后端 + LVGL 界面）**确实编进固件了，也在板上跑起来了**。
音频电通路和串口语音链路都在线。
**唯一没通的是喇叭出声这件事**，原因不在软件，在板上没插喇叭（见第 5 节）。

## 1. app 到底有没有进固件

### 先说遇到的坑

板级的 `bsp_voice_link.c` 和 app 的 `mianyu_app_main.c` 里，各自都写了一个
`int mianyu_main(int argc, char *argv[])`。

`CONFIG_INIT_ENTRYPOINT = mianyu_main`，链接器找 init 入口时先碰上了板级那个 .o，
于是 app 的 `mianyu_app_main.o` 压根没从静态库里被拉出来 ——
`libapps_mianyu.a` 整个成员都被丢了。

编译日志全绿，ninja 退出码 0，但固件里没有哄睡主循环。
旧固件（`nuttx_audio11.bin`）启动时打的是板级那行：

```
[vlink] mianyu_main: 产品模式启动（无 nsh 控制台，串口归语音链路独占）
```

典型的假通过：日志有，逻辑没有。

### 怎么修的

把板级那个函数改名成 `vl_product_hold()`，只当兜底用（万一 app 没编进来，
让它占住 init 线程，系统不至于因为没入口跑飞）。语音链路本来就不靠这个符号，
它是 `board_late_initialize()` 里 `bsp_voice_link_start()` 单独拉起来的。

### 修完怎么确认的

```
$ nm nuttx | grep -E " (T|t) (mianyu_main|vl_product_hold)$"
1202cced T mianyu_main                 # 只剩一个，来自 app

$ nm .../mianyu_app_main.c.o | grep mianyu_main
00000001 T mianyu_main                 # 这个符号确实出自 app 的目标文件
```

`vl_product_hold` 被 `--gc-sections` 丢掉了（没人引用）——说明 app 的入口真被选上了，
兜底没用上。

app 侧的符号也都在：

```
12031a3d T my_breathe_init
12030209 T my_fade_init
120325b5 T my_hal_audio_play
12032615 T my_hal_light_set
12030e0b T my_mem_init
1202e1c9 T my_sched_init
1202f449 T my_sleep_init
```

### 体积对得上

| 固件 | 大小 | 说明 |
|---|---|---|
| `nuttx_audio11.bin`（改前） | 1571940 B | app 没链进去 |
| `nuttx_audio12.bin`（改后） | 1639192 B | 多了 67252 B，就是 app 核心 + HAL + 字体 |

flash 占了 9.77%（16 MB），sram 34.85%（512 KB），psram 0%。

## 3. 语音链路（板子一直在往上发）

板上跑起来后，链路心跳那几行（夹在二进制 PCM 流里，得从原始字节里抠出来）：

```
[vlink] 上行 672 帧 下行 0 帧 | 麦克风 HT=84 TC=84(Δ8) | 待放=0 样本 |
        TX 350277 字节 丢帧 0 | CRC错=1 重同步=3 | cfg=MIC-UP
[vlink] 上行 704 帧 下行 0 帧 | 麦克风 HT=88 TC=88(Δ8) | 待放=0 样本 |
        TX 366949 字节 丢帧 0 | CRC错=1 重同步=3 | cfg=MIC-UP
```

| 指标 | 读数 | 怎么看 |
|---|---|---|
| 上行帧数 | 672 → 704（20 秒里 +32 帧） | 大概 1.6 帧/秒，一直在推 |
| 丢帧 | 0 | 上行没丢 |
| CRC 错 / 重同步 | 1 / 3 | 只有开机握手那会儿有，之后不再涨 |
| TX 字节 | 350277 → 366949 | 差不多 833 B/s，就是上行 PCM 的实际带宽 |
| 麦克风 HT/TC | 84/84 → 88/88 | MIC 那边计数稳定（HT 半满，TC 满） |
| `待放=0 样本` | 下行缓冲是空的 | 这轮没发下行音频，正常 |

结论：板子当"耳朵 + 嘴 + 按键"用的串口链路，在真机上是通的，上行最怕丢的 PCM 也是零丢帧。

## 5. 喇叭这件事：没出声

### 怎么测的

在板上放本地 1 kHz 音源，然后看麦克风收到的 1 kHz 有多少。分两组对照：

- B 组：功放使能（PA10 = 1）。喇叭要是响了，麦克风应该能多收到一份"空气传过去"的 1 kHz
- C 组：功放关掉（PA10 = 0）。那就只剩板内 DAC 输出结点到 MIC 的电耦合

判据很直接：**C 组跟 B 组差不多，就说明麦克风里的 1 kHz 全是电耦合过来的，喇叭没响。**
每组叠 12 个窗（约 0.8 秒）压方差 —— 单个窗读数跳得太厉害，没法判断。

### 结果（`sound_card.py`，多窗平均）

| 组 | 放音 1kHz | 邻近 750/1250 Hz | 1kHz / 邻近 |
|---|---|---|---|
| B 功放开 | 73.5 | 9.5 | 7.74× |
| C 功放关 | 88.5 | 9.5 | 9.32× |

**B / C = 0.83** —— 把功放关了，1 kHz 反而更高。

### 怎么看

- 麦克风确实收到了很强的 1 kHz（比邻近频率高 8~9 倍，远超 4 倍的判据）→ DAC 输出通路是活的
- 但功放开和关，读数没差别（0.83×）→ 这点 1 kHz 是 DAC 输出结点串到 MIC 的板内电耦合，不是空气里的声波
- 功放一开读数还略降，符合"功放输入级加载了 DAC 输出结点、串扰降一点"的物理常识

所以：喇叭（J0101）基本没出声。板内音频电通路没问题，声学输出没通。

### 已知的和还没排除的

| 项 | 状态 |
|---|---|
| `BSP_ENABLE_DAC2` | 只有 LB58X 才定义；LB52 的 DAC2 是禁用的 —— 设计如此，不是 bug |
| DAC1（A.33）输出级 `EN_OS_DAC` | 开了 |
| 功放使能脚 PA10 | pinmux 是 `HAL_PIN_Set(PAD_PA10, GPIO_A10, PIN_PULLDOWN, 1)`，运行期也拉高了，确认置位 |
| 功放芯片 U0104（NS4150B） | 软件侧没有更多能控的（没有 I²C 配置） |
| J0101 上到底插没插喇叭 | 最可能的原因，得人去看一眼 |

板上那个喇叭座（J0101）现在是空的，没插喇叭。买个 4Ω3W 的插上去再跑一遍
`sound_card.py`，B/C 比从 0.83 涨到 2 倍以上，就算通了。

## 6. 复现步骤

```bash
# 1. 云机编译
ssh -p <端口> root@connect.nmb1.seetacloud.com
cd /root/vela && source build/envsetup.sh && cd cmake_out/sf32lb52_devkit_lcd && ninja
# 产物 nuttx.bin

# 2. 取回 + 烧录（PC 侧）
sh $TEMP/xm-scp.sh root@<host>:/root/vela/cmake_out/sf32lb52_devkit_lcd/nuttx.bin ./nuttx_audio12.bin
./sftool.exe -c SF32LB52 -p COM6 -b 1000000 write_flash nuttx_audio12.bin@0x12010000

# 3. 抓启动日志
python sniff_boot.py COM6 20 bootlog_app_v12.txt

# 4. 板载 MIC 上行
python listen_voice.py 12 COM6 mic_up2.wav

# 5. 语音链路端到端（先起假服务器，再起网关）
python voice/mock_xiaozhi_server.py --port 8990 &
python voice/gateway.py --source board --sink null --port COM6 --baud 1000000 \
       --server ws://127.0.0.1:8990/xiaozhi/v1/ --wake vad

# 6. 声学回环复验（等喇叭到货）
python sound_card.py
```

小提醒：本机开着系统代理（`HTTP_PROXY=http://127.0.0.1:56601`），
跑第 5 步连本地 ws 会被代理拦成 502。跑之前先
`export NO_PROXY=localhost,127.0.0.1` 并把 `HTTP_PROXY` 之类 unset 掉。

另外板子偶尔会卡住不出数据，RTS 脉冲复位一下就好（`sniff_boot.py` 里已经带了）。
