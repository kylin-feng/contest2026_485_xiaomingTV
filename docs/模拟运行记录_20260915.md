# PC 模拟运行记录（2026-09-15）

这份是**保底演示**的存档：不开真机、不接板子，只在一台普通 PC 上把整个作品的
逻辑跑一遍，并把原始输出存下来。真机是主战场，但真机受硬件（喇叭、排线、烧录）
制约，评审和演示都需要一份随时可复现的等价物 —— 就是这里。

结论先写：**三条命令全部通过，无一条失败**，且这一版把「Agent 下发光引导参数」
这条下行闭环补进了模拟器，所以 PC 上也能看到完整的「判定上行 + 命令下行 → 灯真的变了」。

## 怎么跑（评审可自行复现）

只要一个 C 编译器和 Python 3，不需要 make：

```bash
python tests/pc_build.py report   # 六个模块的单元测试，含逐套件断言统计
python tests/pc_build.py demo     # 整晚闭环演示
python tests/pc_build.py app      # HAL 接入版真机主循环（PC 模拟后端）
```

## 三、HAL 接入版主循环（app，即真机固件的同一份主循环代码）

**模拟区间**：22:05:00 → 07:10:00，共 30600 s，步长 5 s（主循环 100 ms 一 tick）。
**原始输出**：`logs/pc_sim_app_20260915.log`（6688 行）
**md5**：`98fb19cfe0022725afc51f94ef3521a3`

### 上行（判定 → Agent）：113 条

| 上报内容 | 条数 |
|---|---:|
| 已入睡 | 99 |
| 清醒 | 12 |
| 困倦 | 2 |

上行按「状态变化立刻报 + 状态不变每 5 分钟一次心跳」的策略发，所以 113 条不是
采样点数（30600 s / 5 s = 6120 个采样点），而是真正值得报的 113 次。

### 下行（Agent → 光引导）：5 条，且真的改变了灯

| 模拟时刻 | Agent 下发 | 板子回执 | 灯的变化 |
|---|---|---|---|
| 22:12:00 | SET_BREATHE 吸 4000 / 屏 2000 / 呼 6000 ms，峰值 35% | `← Agent 改呼吸节拍` | 节奏立刻从默认值切过去 |
| 22:20:00 | SET_HALO 60% | `← Agent 改光晕峰值：60%` | 灯值随后出现 60%（92 次采样） |
| 22:40:00 | LIGHT_ONOFF 开 | `← Agent 开灯` | 会话期内灯不再恒 0 |
| 23:10:00 | SET_HALO 25% | `← Agent 改光晕峰值：25%` | 灯值回到 25%（421 次采样） |
| 06:30:00 | LIGHT_ONOFF 关 | `← Agent 关灯` | 晨间收灯 |

灯值分布可交叉验证：`灯=60%` 92 次、`灯=25%` 421 次，其余多为 0% 与呼吸中间值
（4%/8%/9%/14%/15%/19%/22%…）。**22:12 之前灯恒为 0%**，命令之后才有值 ——
这证明下行不是"日志里说改了"，而是真的改了主循环里的 `breathe.cfg.peak_pct`。

### 判定与界面状态

- 判定：`[入睡]` 5935 次、`[清醒]` 603 次（占比与整晚生理过程相符：前 20 分钟清醒，
  之后进入入睡态，夜间有 1 次夜醒）。
- 界面状态机（`[ui]`）走全了一条链：
  `表盘待机 → 引导中 → 已睡着 → 夜醒安抚 → 判定中 → 已睡着 → … → 表盘待机`。

## 四、本轮对模拟器做的改动

**`app/mianyu/hal/sim/mianyu_hal_sim.c`：`my_hal_remote_cmd_take()` 从"恒 false"
改成按虚拟时钟放一段下行脚本。**

改之前的模拟器只有上行：`make app` 里永远看不到 `← Agent …` 那些行，因为 PC 侧
没有对端发命令。改之后，脚本按虚拟时刻（相对 22:05:00）依次投递 5 条命令，
主循环的下行分支（`while (my_hal_remote_cmd_take(&rcmd))`）被真正走到一遍。

**这个改动只动模拟后端**：真机后端 `hal/sf32lb52/mianyu_hal_vela.c` 与板级
`board/bsp_voice_link.c` 一行未改，所以真机还是"命令从串口来"。

## 五、这份记录不证明什么（诚实边界）

- 这是 **PC 模拟**，不是真机。它证明的是"逻辑闭环能跑通、上行下行都有人接"，
  **不证明**屏上有像素、不证明喇叭出声、不证明真人收音。
- 模拟器的 MIC 是合成信号（Goertzel 可判的呼吸正弦 + 噪声），不是真人躺床上的声音。
- 真机证据在 `docs/真机运行证据_20260914.md`、`docs/手表界面_真机验证_20260915.md`
  与 `logs/` 下那几份串口原始日志里。
