# 真机显示与触摸：定性过程与结论（2026-09-15）

最终固件：`nuttx_v43.bin`，1677420 字节，md5 `8db381c7dc69c8b604e9e3ca24683042`，地址 `0x12010000`。
原始日志：`logs/真机_v43_显示触摸.txt`（v39/v40/v41/v42 的失败版保留在 `logs/` 里，见第 6 节对照表）。

这一轮的目标只有一句话：**把"界面显示没跑通"这件事从"猜"变成"定性"**。
手段是让写路径自己说话 —— 全屏纯色循环、wrram 埋点、触摸电气检测，三件事一次上板。

---

## 1. 结论

**显示通路是好的，界面在真机上跑起来了。**

v43 上板数据（`t` 为心跳线程自己的计时）：

```
[lcd][diag] /dev/lcd0 registered (took 0 retries)
[lcd][pa] first putarea rows=0..71 cols=0..389 bpp=16 stride=780    <- 首帧就是真实整屏
[mianyu] 触摸已补挂 indev=0x20041600

[lcd][hb] t=5s  putarea=28(+28)  wrram=76(+76)   done=76(+76)   timeout=0
[lcd][hb] t=10s putarea=63(+35)  wrram=171(+95)  done=171(+95)  timeout=0
[lcd][hb] t=25s putarea=140(+9)  wrram=380(+23)  done=380(+23)  timeout=0
[lcd][hb] t=30s putarea=140(+0)  wrram=380(+0)   done=380(+0)   timeout=0
```

`done == wrram`、`timeout == 0` —— 推给面板的每一次写都完成了，一次都没超时。
30 秒后 `putarea` 停止增长是**预期行为**：界面静止时脏区为 0，LVGL 一次刷新都不发
（这条是 09-15 早些时候的渲染优化，见 `手表界面_真机验证_20260915.md` 第 3 节）。

**触摸**：I2C1 电气正常，驱动注册成功，LVGL 已挂上 indev。
能否真正响应手指，需要人工点一下（第 5 节）。

**IMU 没接**：`LSM6DS3 not found at 0x6a on I2C1: -5`，与触摸同一条 I2C1 总线。
两个器件都不应答，指向"这两颗芯片本批板子上没焊"。

## 2. 写路径长什么样（后面所有推理都基于这条链）

```
LVGL flush_cb
  -> ioctl(LCDDEVIO_PUTAREA)
  -> sf32lb_lcd_putarea()
  -> sf32lb_lcd_wrram()
  -> WriteMultiplePixels()          (co5300)
  -> HAL_LCDC_SendLayerData2Reg_IT()
  -> LCDC 完成中断 -> sem_post(draw_sem)
  -> 写者 sem_timedwait(draw_sem, 200ms)
```

关键点：**`draw_sem` 是整机唯一一个完成信号量**，谁在等它，就代表谁在写面板。
而且 `sf32lb_lcd_putarea()` 在 `!s_lcd_hw_ready` 或 `s_fb_registering` 时
**静默 `return OK`** —— 调用方以为刷成功了，其实一个像素都没发。

这个静默返回是整轮排查的起点：它让"没画"和"画了但看不见"在日志里长得一模一样。

## 3. 三段式排除：怎么一步步逼出真因的

### 第一刀：写通路本身到底通不通（v39）

做法是把屏幕从 LVGL 手里拿走，在 `/dev/lcd0` 注册之前跑一段**全屏纯色循环 + 扫动条**，
每一像素都走 `sf32lb_lcd_wrram()` —— 和 LVGL 逐字节同一条路。

```
[lcd][itvis] start: LVGL write path, 390x450, band=8
[lcd][itvis] white pushed (wrram=57   done=57   timeout=0)
[lcd][itvis] red   pushed (wrram=133  done=133  timeout=0)
[lcd][itvis] green pushed (wrram=209  done=209  timeout=0)
[lcd][itvis] done: wrram=912 done=912 timeout=0 kb=5392
```

**结论：QSPI 像素通路完全通畅。** 顺带把 `0x2E GRAM 回读 NO MATCH` 那条老警报
定性成假警报 —— 是读路径（`dummy_clock=0`）不可信，与写无关。

那屏上为什么没有界面？只剩一个可能：**LVGL 那一侧根本没在写。**

### 第二刀：LVGL 到底写没写（v40）

加了 putarea / drop / first-write 计数和 5 秒心跳。

```
[lcd][pa] DROP #1 rows=0..449 cols=0..389 hw_ready=0 fb_reg=1
[lcd][hb] t=5s putarea=0 wrram=0 ...
```

**首帧是整屏，被静默丢掉了**，而且之后 `putarea` 一直是 0。
丢帧是真的，但`putarea=0` 说明问题比丢帧更靠前 —— LVGL 压根没拿到设备。

### 第三刀：谁在挡着设备节点（v41）

v41 做了一个"看起来更对"的改动：把 IRQ、图层配置、`s_lcd_hw_ready=true`、
bring-up 纯色测试**整块前移到 `lcddev_register` 之前**，理由是"面板必须比设备节点先就绪"。

结果暴露了真正的瓶颈：

```
[lcd][itvis] white pushed ...
[mianyu] 等 /dev/lcd0 超时，界面不启动        <-- 就这一行
[lcd][itvis] done: wrram=912 done=912 timeout=0
[lcd][diag] panel ready before lcddev_register
```

**根因在这里：`itvis` 挡在 `lcddev_register` 前面，把应用侧等 `/dev/lcd0` 的 20 秒窗口撑爆了。**

- co5300 那一长串初始化命令 + 面板自检实测要十几秒；
- `itvis` 912 次写（每次 6240 字节，QSPI 50MHz）再加 6.5 秒休眠，实测又要十几秒；
- 两段叠起来 > 20 秒，而应用侧写的是 `my_wait_dev("/dev/lcd0", 20000)`，
  **等不到就 `return`** —— LVGL 线程直接退出，界面从此永远不会起来。

所以"界面显示没跑通"最终是这个形状：**不是驱动不会画，是界面线程在等设备节点时死掉了。**

## 4. 修法（v42 / v43）

三处改动，都指向同一件事：**让 `/dev/lcd0` 尽早出现，并且等的人不许放弃。**

**(1) 驱动：bring-up 测试不再挡在注册前面**

```
Init -> IRQ -> 图层 -> s_lcd_hw_ready = true -> lcddev_register()   <- 注册第一优先
                                                    |
                                    注册成功后，可视测试才另起线程跑（默认关）
```

**(2) 应用：等设备节点改成不许放弃**

```c
/* v41 真机日志：「等 /dev/lcd0 超时，界面不启动」—— 原来等 20 秒等不到就 return，
 * 界面从此永远不起来，屏幕自然一直是黑的。这是「界面跑不通」的最后一道门。 */
for (;;) {
    if (my_wait_dev("/dev/lcd0", 5000)) break;
    syslog(LOG_ERR, "[mianyu] 仍在等 /dev/lcd0（板级 LCD 尚未注册完）\n");
}
```

**(3) 驱动：写路径加锁**

v40 曾出现 7 次 `xfer TIMEOUT errno=110`：`itvis` 与 LVGL 并发写同一个 `draw_sem`，
后到者把别人等的令牌 drain 掉了。加一把二元信号量把 `wrram` 串起来，
超时路径也照常释放，不让一次超时把 LCD 卡死整个启动过程。

v43 再清掉两处噪声：bring-up 全屏循环永久关闭（它已经完成使命，只会盖住界面 8 秒），
以及一段 `if (0)` 死代码留下的 `ERROR: lcd_visual task_create failed: 0` 误报。

## 5. 还剩下的（人工项）

**屏幕肉眼确认。** 日志能证明"像素发出去了"，证明不了"你看到的是对的那幅画"。
板子现在跑的就是 v43，直接看：

1. 开机后应停在**表盘页**：大时间、日期、「开始哄睡」按钮。
2. 点「开始哄睡」→ 应切到**哄睡页**，中间三层呼吸光晕缓慢明暗。
3. 点左上「返回」→ 回表盘，按钮文字变「回到哄睡」。
4. 长按「返回」→ 结束今晚。

第 2 步同时验证触摸：**光晕会动 = 触摸可用；点了没反应 = 触摸芯片确实没焊**。

**IMU**：`LSM6DS3 -5` 与本轮无关，先按未焊接处理。

## 7. 复现步骤

```bash
# 1. 云机编译（构建目录是 ninja；envsetup.sh 在 sh 下用 . 不要用 source，
#    没有 lsb_release 会返回非零，脚本里别加 set -e）
cd /root/vela && . ./build/envsetup.sh
cd cmake_out/sf32lb52_devkit_lcd && ninja -j96
md5sum nuttx.bin

# 2. 烧录（板子跑起来后 UART 一直在吐帧，sftool 的 stub 握手会被撞掉，
#    --connect-attempts 6 或直接重试 2~3 次即成功）
flash_v43.py 100 v43        # 烧 nuttx_v43.bin 到 COM6 并抓 100 秒日志
```

日志里要盯的四个字段：`putarea` / `wrram` / `done` / `timeout`。
判据是 `done == wrram` 且 `timeout == 0`；`drop` 保留 1 次是正常的
（`fb_register()` 内部那次清屏，被 `s_fb_registering` 挡掉，设计内）。
