# Night Wake

夜醒安抚 Skill：用户在半夜醒来时轻声接住，不亮屏、不追问、不聊天，
用最轻的干预帮用户尽快回到睡眠。

## When to use
- 夜间（入睡后、晨唤前）检测到用户体动明显或发出声音，疑似醒来
- 用户主动出声（"睡不着 / 醒了"）——注意：半夜的请求要极简响应
- 夜醒判定模块上报"疑似夜醒"

## How to use
1. **先安静判断，不要抢答**：
   - 若只是翻身/短暂体动，**不触发任何响应**——多数翻身不是醒来，多嘴反而吵醒。
   - 持续体动超过阈值或检测到语音，才进入安抚流程。
2. **最轻干预优先**（按顺序尝试，能停就停）：
   a. 恢复播放入睡时用的噪声（音量 ≤ 25%，比睡前更低）——声场回来了，
      人容易再睡回去。
   b. 若 2 分钟内仍清醒，用**最低音量**说一句不带问句的安抚：
      "我在。跟着我呼气。"——**不提问**（"怎么了？"会启动大脑思考）。
3. **不亮屏原则**：安抚全程保持屏幕熄灭/极暗（呼吸灯除外），任何画面
   都会让大脑从"睡眠模式"切到"处理模式"。
4. **记录**：把夜醒时间与安抚手段追加到当日睡眠记录（供晨间回顾聚合
   night_wake_count，不打扰用户）。

## Important
- **安静 > 陪伴**：夜间干预的黄金法则是"用最小的声音、最短的话、最快的离开"。
  一次安抚后**不追问效果**，30 分钟内不再重复触发同样话术。
- **禁忌清单**：
  - 不提问开放式问题
  - 不播报时间（"现在凌晨 3 点"会让人算自己还能睡几小时——瞬间清醒）
  - 不聊天、不讲故事接龙、不报新闻
- **连续夜醒的升级**：若 3 次以上夜醒间隔 < 1 小时，可能是环境问题（冷/热/亮），
  留到晨间回顾时温和提及，**不在夜里分析**。
- **传感器不可用（模拟器/无 MIC）时的降级**：无法检测夜醒则**不主动触发**，
  仅在用户明确出声时执行"最轻干预"；不得假装检测到夜醒。
- 合规：放松陪伴，非医疗建议，不承诺治疗效果。

## Example
User (02:10, 迷迷糊糊): "……几点了"
→ 判定真夜醒 → 极低音量微光 + 恢复棕噪 15%
→ "还早。我在，跟着我呼气。"（故意不报时间——深夜报点会让人
   开始算"还能睡几小时"，瞬间清醒）
→ 用户翻身又睡 → 静默，屏幕保持熄灭，30 分钟内不重复触发
→ 追加夜醒记录 → 结束（不再回复）

## Example (翻身误判规避)
(00:40, 一次短暂体动后恢复平静)
→ 不触发任何响应
→ (继续静默)
