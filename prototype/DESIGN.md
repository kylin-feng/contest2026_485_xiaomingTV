# 眠屿 SleepIsle S1 —— 硬件陪伴哄睡 Agent 设计文档

> 版本 v0.2 · 2026-10 · 配套：`prototype.html`（原型图）、`index.html`（可交互模拟器，Agent 逻辑已跑通）
>
> 一句话：**不是白噪音音箱，是整夜值守的哄睡 Agent——感知你的呼吸与夜色，把光、声、温、帘编排成一夜好眠。**

---

## 1. 产品定位与北极星

**品类**：床头「睡眠编排中枢」（Sleep Orchestrator），不是监测设备，不是音箱。

**为什么现在**：
- Hatch Restore 验证了"床头哄睡硬件 + 订阅"能赚钱（2025 年营收 2 亿美元）；
- Oura/手环把"睡眠监测"做成标配，但**监测不产生干预**——用户知道自己睡不好，却没人帮他睡好；
- 米家生态里床（8H）、灯、空调、窗帘、手环全都有，唯独缺一个让它们"在正确时间做正确动作"的睡眠大脑。

**北极星指标**：用户平均**入睡潜伏期缩短分钟数**（目标：4 周内 -20%）。

**三个不做**：
1. 不做屏幕（睡前最后一小时不该有屏幕，这是产品哲学也是差异化）；
2. 不做摄像头（卧室隐私红线，物理上没有）；
3. 不做床垫/枕头/戒指（8H、Sleepal、今日宜休已占位，我们做它们的指挥）。

## 2. 用户与场景

| 人群 | 痛点 | 我们给的 |
|---|---|---|
| 25-35 岁高压都市人（主） | 躺下脑子停不下来，手机越刷越精神 | "数字日落"：用光与声把手机请出卧室，Agent 接管入睡仪式 |
| 浅眠易醒者 | 半夜醒来看时间→焦虑→更难睡 | 夜醒陪护：耳语响应、故意不报精确时间、音景 25% 陪护 |
| 伴侣同床（一方打鼾/作息不同） | 鼾声干扰、一方起夜开灯 | 鼾声掩蔽层、起夜微光（只亮脚边） |
| 银发/养老（B 端扩展） | 夜间跌倒、呼吸异常无人知 | 雷达无感监测+异常告警（Sleepace 已验证 B 端付费意愿） |

**核心场景闭环**：日落陪伴 → 入睡护航 → 深睡守护 → 夜醒哨兵 → 日出唤醒 → 晨间报告。
（详细时间轴与剧本见 `prototype.html` 第 03/05 节。）

## 3. 竞品与生态位

```
床上层（床垫/枕头）：  8H 趣睡（米家系）❌ 不做
感知层（床头雷达）：   Sleepal（范典，$449 医疗级单品）⚠️ 相邻物种
穿戴层（戒指）：      Oura / 今日宜休（王腾）❌ 不做
干预层（灯/声）：     Hatch（美国）· 国内空白 ✅ 我们的入口
编排层（睡眠大脑）：   ★ 完全空白 ★ 我们的护城河
```

**对 Sleepal 的差异化**：它做"医疗级精度的高端感知单品"（不联网、隐私优先、$449）；我们做"**普惠中枢 + 编排米家存量设备**"（¥599-799、连接是核心能力）。它的终点是全屋健康入口，与我们会在 2-3 年后相撞——先发优势在编排协议和记忆数据。

## 4. 硬件设计

### 4.1 形态与 CMF
- 形态：半球"小月亮"，⌀120 × 86mm，480g。环形柔光罩是它的"表情"——灯效即 UI。
- CMF：织物网罩（燕麦/暖灰，Hatch 验证了"去科技感织物风"对 Gen Z 的杀伤力）+ 哑光铝底座 + 磨砂柔光罩。
- 三视图与传感器布局见 `prototype.html` 第 01 节。

### 4.2 传感器选型（感知层）
| 传感器 | 用途 | 选型理由 |
|---|---|---|
| 60GHz 毫米波雷达 | 呼吸率/体动/在离床 | 穿被子可测、无接触、无隐私负担（Sleepal 已验证工程路径） |
| 4 麦远场阵列 | 鼾声/梦话/环境噪音/语音指令 | 语音入口 + 噪音感知二合一 |
| 温湿度 + 环境光 | 环境基线 | 低成本，支撑空调联动决策 |
| ~~摄像头~~ | — | **不放**。卧室红线。 |

### 4.3 执行器（执行层）
- 环形灯 RGBW 1800-4000K：日落（8min 渐暗至熄）、呼吸练习光圈、日出（20min 渐亮）。
- 1.75″ 全频 + 无源辐射器，夜间限幅 65dB；**5 层音景混音台**实时合成（非录音循环）：
  `底噪 base / 场景 tex / 遮蔽 mask / 点缀 detail / 晨鸟 birds`，Agent 逐层推子。

### 4.4 物理交互（半夜盲操作设计）
| 动作 | 功能 |
|---|---|
| 轻拍顶部 | 晚安 / 暂停 |
| 顺/逆时针滑触控环 | 音量 |
| 捂住顶部 2s | 立即熄灯静音（"别烦我"手势） |
| 背面物理拨杆 | 麦克风断电（机械级隐私） |

### 4.5 成本与定价
BOM ≈ ¥220 → **售价 ¥599-799**；订阅 ¥15/月（音景内容库 + 深度睡眠报告 + Agent 个性化话术）。
商业公式 = Hatch 验证过的 **公式 A：硬件走量（入口）+ 订阅（利润）**，订阅留存的关键是"每日打开理由"= 晨间报告 + 每周新音景配方。

## 5. Agent 系统设计（核心）

### 5.1 四层闭环（每 3 秒一轮）
```
感知 SENSE → 雷达/麦克风/温湿度/米家手环 → 呼吸率、体动、鼾声、噪音、睡眠阶段
记忆 MEMORY → 个人基线（入睡潜伏期、易醒时段、音景偏好），每晚更新
决策 THINK  → v1 规则引擎(60+ 条) → v2 端侧小模型 → v3 云端 LLM 话术生成
执行 ACT    → 5 层音景混音 / 灯光 PWM / TTS / 米家设备编排
↺ 闭环自检：执行改变环境 → 传感器读到变化 → 下一轮校准（例：自己放的音景反而吵到用户→自动降）
```

### 5.2 v1 六条核心规则（已在 index.html 模拟器跑通）
| # | 触发（感知） | 行动（执行） |
|---|---|---|
| R1 | 环境噪音 > 45dB | 遮蔽层 +12%（上限 50%）；安静后缓慢收回 |
| R2 | 检测到鼾声 | 遮蔽层 +5% 掩蔽，不打扰睡者 |
| R3 | 体动（翻身） | 场景层闪避 3 秒——声音不抢注意力 |
| R4 | 睡眠阶段换挡 | 深睡：场景层降至 25%；REM：保留掩蔽 40% |
| R5 | 呼吸 <10 且入浅/深睡 | 启动 20 分钟整晚渐弱计划 → 静默纯监测 |
| R6 | 深夜呼吸率回升+连续体动 | 夜醒陪护：耳语 + 音景 25% + 灯保持熄灭 |

### 5.3 记忆层（差异化核心，模仿者最难抄的部分）
- 每晚 A/B 微调：雨声 vs 海浪，哪个让你呼吸率降得更快；
- 周报输出："海浪让你平均快 6 分钟入睡"；
- 长期基线：识别"你周四总是难入睡"（周会日）→ 周四自动提前 15 分钟启动日落。

### 5.4 状态机
`待机 → 日落陪伴 → 入睡护航 → 深睡守护 ⇄ REM 掩蔽 → 日出唤醒 → 晨间报告 → 待机`
异常回路：任意睡眠态可切入 `夜醒陪护`，10 分钟无响应自动回落，重新入睡后回到守护态。

### 5.5 话术设计原则
慢（0.82× 语速）、短（≤20 字）、暖（不说教）、深夜一律耳语音量；**夜醒不报精确时间**（"还早，才三点"——减少睡眠焦虑，这是 Hatch 产品访谈里反复出现的洞察）。

## 6. 生态与平台策略

- **OS**：openvela（小米 Vela 开源版）——参赛叙事："米家生态床、灯、空调、手环都有了，我们用 openvela 做了把它们连成'一夜好眠'的大脑。"
- **米家接入**：作为中枢编排——日落时关大灯拉窗帘、入睡后空调调 24.5°、起夜时脚边微光、日出前窗帘开缝、起床确认后全屋恢复日间模式。
- **数据入参**：可选读取米家手环/手表睡眠数据，与雷达互校验，提升分期准确率。

## 7. 隐私与安全（卧室设备的生死线）
1. 无摄像头（物理不存在）；2. 麦克风物理断电拨杆；
3. 雷达只输出特征值，原始点云端侧销毁；4. 整夜本地闭环，云端仅匿名周报（可关）。
隐私不是合规成本，是**营销资产**——"数据不出卧室"印在包装盒上。

## 9. 验证指标

- **功效**：入睡潜伏期（主）、WASO（夜醒时长）、主观量表 ISI/PSQI 4 周改善；
- **产品**：7 日留存（公式 A 的命门）、语音互动率、晨间报告打开率、订阅转化；
- **Agent 质量**：规则触发准确率（误触发率 <5%）、夜醒响应满意度、A/B 偏好收敛速度。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 睡眠分期不准导致误干预 | 阈值保守化（宁可不动，不可乱动）+ 手环数据互校验 + "捂住顶部"一键否决 |
| 雷达+BOM 推高成本 | P2 先出无雷达 Lite 版（¥399，麦克风+手环数据），验证需求后再上雷达版 |
| 小米自己做 | 这正是参赛/接入生态的双刃剑——做到"被收购也值"的位置，或跑得快到成为事实标准 |
| 订阅留存低（Dodow 前车之鉴） | 内容库周更 + 记忆层个性化报告 = "每日打开理由"；订阅失败也能靠硬件毛利活 |
